# web: the Ajayeb client

The browser client: a static SvelteKit 2 app with Svelte 5 runes, Tailwind 4, Vite 8 and TypeScript 6.0. It is thin on purpose. The Go server holds the only rules engine; this app renders the views the server sends and sends back action keys. See [AGENTS.md](../AGENTS.md) for the conventions and [docs/architecture.md](../docs/architecture.md) for the data flow.

## Running it

Heavy commands go through the root `Makefile`, which wraps them in the memory guard (`tools/heavy.py`):

- `make check-web` runs `svelte-kit sync` and `svelte-check` (the type gate).
- `make lint-web` runs ESLint and `prettier --check`.
- `make test-web` runs the Vitest unit tests (one worker thread).
- `make build-web` writes the static build to `web/build/`; `make build` embeds it in the Go binary.
- `python3 self_host.py dev-start` runs the Go server and the Vite dev server together (see `make dev`). Use it only for attended development in the main checkout. Worktrees and unattended checks use the test build served by Go.

The package scripts behind them are `dev`, `build`, `preview`, `check`, `lint`, `format` and `test`.

Ports: Vite dev listens on 38952 and `vite preview` on 38953. Both forward `/ws`, `/api` and `/health` to the Go server at `http://127.0.0.1:38951`, or to `AJAYEB_SERVER` when that is set.

## Home loading

Home alone is prerendered at build time (`src/routes/+page.ts`), so its real
hero, logotype and mode buttons paint before JavaScript. The generated
`index.html` contains that Home view. `shell.html` is the separate generic
client shell for game links and all other routes; the Go static handler
prefers it for missing app paths, with `index.html` retained for older builds.
The service worker caches the generic shell for offline navigation, so a
room link never hydrates Home's markup. Deploy the entire build together.

The Home build hook keeps CSS, font and hero discovery ahead of the existing
module preloads. Stylesheets keep their cascade order and precede font and
hero preloads. Every module preload has `fetchpriority="low"` and still fetches
eagerly. The hook moves those tags within the head without removing a
resource or changing body and hydration markup; other routes and the generic
shell keep their generated order. The Go server derives a Home-only HTTP
`Link` preload for its largest generated stylesheet from the same HTML digest,
so it starts before the browser scans smaller CSS and module requests.

The hero is eager and high priority. Its preload and image share the
responsive source set from the generated art index, including content hashes.
Priority art paints without waiting for an image-load state update. Art load
listeners attach through the DOM, avoiding inline event attributes under the
server CSP and handling a cached success or failure before hydration. Dark Home
frames the painting without a paper feather.

Before mount, Home's buttons and theme fieldset have native `disabled`
semantics, dimmed styling and a visible translated “Getting ready…” status.
This availability state covers pointer, touch and keyboard activation without
an inline event queue or another CSP allowance. A player must wait until the
controls become available, then activate once. The tradeoff is a short visible
wait rather than accepting an early action and replaying it later. The no-script
Home remains readable with explicitly unavailable controls and working links.
Continue and the tutorial offer appear only after mount, when their actions
are already available. Production smoke helpers still click immediately after
the heading; native disabled semantics make their click wait safely.

Home loads each sheet on first open and retains it for subsequent opens.
The live session loads on the first create; `saved-rooms.svelte.ts` owns the
one saved-room store and storage listener shared by Home and the game.
Saved rooms and the tutorial offer appear after mount, preserving hydration
and preventing returning players from briefly seeing the first-launch offer.

## Layout

- `src/app.html` is the page template. Its inline script applies the stored theme before the first paint, so the page never flashes the wrong theme.
- `src/app.css` imports Tailwind and the tokens, declares the fonts, maps the tokens to Tailwind utilities, and holds the base styles (the `100dvh` app shell, the safe-area variables `--safe-t`, `--safe-r`, `--safe-b`, `--safe-l`, focus rings and the styles for Animation off).
- `src/lib/styles/tokens.css` is the single source of colour, type and motion tokens, in OKLCH. Cards keep their paper colours in both themes; only the table surfaces change, from an ivory manuscript page (light) to lapis night (dark).
- `src/lib/i18n/` holds the message tables and `t()`.
- `src/lib/ui/` holds UI state classes, such as the theme (`theme.svelte.ts`) and the safe-area override (`safe-area.ts`), and small display mappers such as the military track's side (`track.ts`) and the online helpers (`online.ts`: the room-code input normaliser and alphabet, the invite link, seat presence and its changes, the QR path).
- `src/lib/dev/flags.ts` decides whether the `/dev` routes exist.
- `src/routes/` holds the pages. `/` is Home, `/play/<code>` is a room, `/rules` is the rules reference, and `/dev/*` holds the developer pages.
- `static/` is served as is under stable names: the font licenses, the favicon, the web manifest and app icons, and the approved bitmap art under `static/art/` (see Bitmap art).
- `src/lib/fonts/` holds the shipped WOFF2 fonts and their licenses. `src/app.css` names them, so the build emits them under content-hashed URLs in `/_app/immutable/assets/`.
- `font-sources/` keeps the original TTF fonts and `subset.sh`, which rebuilds the shipped WOFF2 subsets in `src/lib/fonts/`.

## Session: talking to the server

`src/lib/session/` is the client's whole connection layer. It decides nothing about the game: what may be played is the view's `choices`, what it costs is their cost breakdowns, and whether this client may act comes from the state frame. [docs/protocol.md](../docs/protocol.md) is the contract it implements.

- `transport.ts` defines the Transport (send, onMessage, onState, close, and an optional `reconnect` that drops the socket and opens a new one). `ws-transport.ts` is the WebSocket to `/ws` on the page's origin, with reconnects (exponential backoff with jitter, capped at 15 s; no retry after a 1008 `protocol` or `bad-hello` close). The browser's `offline` event drops an open socket at once, so the page shows the offline state and sends nothing, and its `online` event retries without waiting for the backoff. `fixture-transport.ts` answers from recorded frames, for dev pages and tests, and `scripted-transport.ts` is driven by hand in unit tests.
- `identity.ts`: the identity token in `localStorage` (`ajayeb:token`, 22 base64url characters, never logged), a random client id per page load, and the display name (`ajayeb:name`).
- `session.svelte.ts`: the Session. It says `hello` on every socket, creates and joins rooms, and sends acts and undos with the tab's `seq` counter and the current version as `base`. It keeps the latest state frame and view in `$state.raw` (replaced whole), the connection state (`connecting`, `open`, `reconnecting`, `offline`), the pending request with a `slow` flag after 300 ms, the last refusal as a message key, and `canAct`. After a reconnect it joins again and re-sends the pending request unchanged. A request the server dropped under its frame rate limit (`reject rate` naming its seq) is re-sent unchanged after a short pause, up to three times, before the refusal shows. `catalogStale` is set when a view's `catalogHash` differs from the client's catalog.
  - `setName(name)` changes the display name the next `hello` sends. When `hello` already went out under another name, it reconnects, so the room shows the new name at once.
  - In a bot room an undo can cross the bot's answer: the server refuses it as `stale` because the answer moved the version. The Session then waits for the fresh state and, if that state still offers undo, sends the undo once more with the same seq and the fresh version as `base`. Only a second refusal shows the stale message.
  - `rematch()` asks for the rematch (a spectator only follows one). `rematchAsked` says this tab asked, so the room page moves to the rematch room as soon as the server's `created` names it; the other player sees the offer on the game-over dialog instead. A request lost to a reconnect is sent again after the join.
- `presenter.svelte.ts`: the Presenter, which holds the frame on screen and moves it forward one queued frame at a time (capture hook, swap, tick, play hook); its animations come from those hooks (see Animations). It paces a bot's answer: a frame that answers a thinking frame waits until the thinking frame has been up `minThinkingMs`, and when the answer takes a card or drafts a wonder it sits in `preview` for `preRollMs` while the old frame stays up. Both settings may be functions; `app.svelte.ts` reads them from the animation speed (`botDwellMs` and `botPickMs` in `ui/motion.svelte.ts`: 700 ms and 300 ms at normal speed, 300 ms each with animation off). A frame with others queued behind it is never paced, `fastForwardAfter` catches up after a reconnect, `hurry()` shows a held answer at once (an undo pressed during the dwell) and `clear()` forgets the room when the game screen goes away. Input is open when `presenter.idle && session.canAct`, so it stays locked through the dwell and the preview.
- `rooms.svelte.ts`: the rooms this browser has played (`ajayeb:rooms`: code, mode and last seen).
- The Session also carries a game's hint settings: `hints` (the room's), `admin` (this user may change them), `canSetHints`, and `roomLog` (the room-level log entries, which `LogSheet.svelte` shows among the moves). `setHints(next)` sends a `hints` frame through the same pending slot and `seq` counter as an act. A `create` without settings takes them from the `defaultHints` option, which `app.svelte.ts` points at the local default below.
- `context.ts` shares a page's Session and Presenter with its components (`setGameContext`, `getSession`, `getPresenter`); `app.svelte.ts` holds the app's one live connection, opened the first time a page needs it.
- `test-hook.ts` defines `window.__ajayeb` for end-to-end drivers (see [docs/testing.md](../docs/testing.md)).
- `replay.ts` downloads the server's log response through a temporary anchor. The menu entry stays disabled with a custom tooltip during play and for hidden finished records; an eligible finished view enables it and adds the result-screen button. The server assigns the UTC dated filename (see [the download contract](../docs/protocol.md#downloading-a-games-log)).
- `DebugBoard.svelte` is a plain view of a room with every choice as a `data-act` button. No page uses it any more; it stays for debugging.

`src/lib/hints/` holds the hint settings on the client (docs/dev/decisions.md D23). `families.ts` lists the twelve families and has the pure helpers: the defaults per mode, the editor's rows, the one-line summary, and `visibleFamilies(roomSettings, localHide)`, the families a screen may show (the game's settings minus what this player hides). `local.svelte.ts` holds two stores in `localStorage`: the local default (`ajayeb:hints`), which a new-game sheet starts from and which is written when a game is created and when its admin changes the settings mid-game (the advisor kept per mode, the other families shared), and the local hide (`ajayeb:hintsHidden`: hidden families, and whether hint marks show on the board). `log.ts` puts the room log among the game log's lines. The components are in `src/lib/components/hints/`: the settings editor, the new-game sheets' collapsible section, the lobby's summary, and the game menu's Hints item with its sheet ("On my screen" holds the local hide).

`src/lib/catalog/` has typed lookups (`cardBySlug`, `wonderBySlug`, `tokenBySlug`) over `src/lib/wire/catalog.gen.ts`, the presentation catalog that `make gen` writes from the engine's data.

The pages: `/play/<code>` joins a room and shows the game screen (`Room.svelte`). A first visit with no stored name, to a room this browser has not created or played, shows `screens/NamePrompt.svelte` first, and only then joins (a join takes the seat under the name at once). A room this browser makes is remembered in the saved rooms the moment it exists: the Session does it on `created` (Home's games and a rematch it asked for) and `createDevRoom` on the dev endpoint's answer, so these open without the prompt. The saved list is read once per code, so a finished game dropped from it never turns back into the prompt. An end-to-end spec that opens a dev room it made with its own HTTP request, in a fresh browser, has to store a name (`ajayeb:name`) first. A room that cannot be opened shows `screens/RoomError.svelte`, with a friendly message for the server's code and a way Home. Home's "Play online" opens `screens/OnlineSheet.svelte` (name, crest, Create, which sends `create` with mode online) and "Join with a code" opens `screens/JoinSheet.svelte` (six characters from the server's alphabet, case-insensitive; a pasted invite link works too); `/dev/new?mode=hotseat|ai|online` creates a room and opens it (with `seed=` or `scenario=`, through the server's dev endpoint); `/dev/fixture/<name>` shows a recorded game state in the game screen with no server.

## The game screen

`src/lib/components/game/GameScreen.svelte` is the board of every mode. It takes the page's Session and Presenter and an `onhome` callback, and decides nothing about the game.

- **Layout.** One markup, with CSS grid areas chosen by `breakpoints.viewport` (`src/lib/layout/breakpoints.svelte.ts`) through a `data-layout` attribute. Phone portrait: top bar, opponent strip, military track and progress tokens, structure (taking the remaining height), own strip, turn bar. Phone landscape: the compact track and tokens move into the top bar, and the strips take side columns. Tablet: stacked, with city bands under each strip. Desktop: city panels in 300 px side columns, 380 px from 1600 px wide. The shell is `100dvh` and never scrolls. During the wonder draft the area between the top bar and the turn bar holds the Draft screen.
- **Player strips** (`city/PlayerStrip.svelte`, phones). The two strips have the same layout and fit in two short rows, so neither ever scrolls. Row 1: the crest (and the bot's avatar), the name (which opens the city sheet), presence, thinking, a military danger shield, the owned progress tokens, coins and victory points (`city/Tally.svelte`: a gold coin pill and a green laurel pill), and the wonder button. Row 2: the five resource chips (production, then the trade price as a coin) and the science count (a green glyph and "n/6"). In phone landscape, where a strip is a narrow side column, the rows wrap: the first always breaks after the name and puts the owned tokens last, so both strips have their tallies and wonder button on one line of their own. Danger warnings (`view/threats.ts`) only show while the game runs and the condition has not already been met.
- **Wonders.** Each player has one wonder button (`wonder/WonderButton.svelte`) reading built/total. When a wonder of the player to move can be built now (`buildableWonders` in `view/wonders.ts` reads the view's `wonder` choices, nothing else), it has an accent ring and a dot. It opens `sheets/WonderListSheet.svelte`, the list of that player's wonders (`wonder/WonderList.svelte`). Each row shows the art (or its placeholder), the name, the cost, a one-line effect and one status: "Built with <card>", "Can build now" or "Not built". The desktop city panel uses the same rows. A row that can be acted on opens the wonder sheet, whose Back button returns to the list.
- **Who sits where.** The board region is `dir="ltr"`. The player is at the bottom (or on the left); a spectator sees seat 0 there. In hot-seat the board faces the player to move on phones and stays fixed elsewhere, with the active panel lit; the setting overrides both.
- **Bottom sheets** (`shell/Sheet.svelte`, used by every sheet) close on Esc, a backdrop tap or a swipe down on phones (`shell/sheet-drag.ts`: from the handle, or from the panel when it is scrolled to its top). The panel and the root element set `overscroll-behavior`, so a pull never reloads the page.
- **The card sheet** (`CardSheet.svelte`) opens on a tapped slot. It shows the card at full tier, its category and effect, the cost breakdown from the matching choice (or disabled choice), the opponent's price and the discard gain, and the Build, Discard and Build a wonder buttons, each with its key as `data-act`. A covered card shows its cover count, no actions, and what each player would pay once it is uncovered, from the server's `costs` on the slot. Build a wonder steps to `WonderStep.svelte`, which lists the player's wonders with cost and affordability. `card-actions.ts` only sorts the view's choices for one card; it never parses keys or computes costs.
- **Wonder first.** Picking one of your wonders from the wonder list (or from the desktop panel) opens `sheets/WonderSheet.svelte`. "Build this wonder" starts the pick mode: the turn bar asks for a card (with Cancel), takeable cards carry a wonder badge, and tapping one opens the card sheet to confirm. Both flows send `wonder:<wonder>:<card>`.
- **Disabled buttons.** The shared shell Button uses the sunken panel, muted ink and a dashed rule border at full opacity. This keeps instructional labels readable and distinguishes unavailable actions from accent-coloured selections.
- **Committing.** Hot-seat and bot rooms send on the tap; online rooms use `ConfirmButton` when the confirm-moves setting asks for it, in the card sheet, in the wonder draft and in every pending choice's commit button. One rule (`game/act-button.ts`) decides each move button's label, whether it is disabled and whether it takes the confirm step, for the card sheet (`ActionButton.svelte`), the pending panels (`choices/CommitButton.svelte`) and the starter choice. On send the sheet closes, the slot shows the pending outline and input locks until the ack; after 300 ms the turn bar shows the slow state. A refusal shows its message above the turn bar.
- **The turn bar** (`hud/TurnBar.svelte`) renders one state from `view/turn.ts`. On a phone it is slim (about 40 px plus the safe area), and its buttons keep a 44 px tap target. A wonder's extra turn reads "Play again (Appian Way)" (or "Sun plays again" in hot-seat) for the whole extra turn: `playAgainFrom` reads it from the game's history up to the frame on screen (the session's `history`, which a join or a resync sends whole), with `view.playingAgain` as the fallback when the history has no source wonder. So a page opened or reloaded during an extra turn still shows it.
- **Toasts** never cover the opponent's strip or the military track. A player's own move gets no toast (they just made it), in every mode; the one exception is a choice the server skipped because it had no option (nothing to destroy, an empty discard pile), which the player could not foresee: a toast gives the line that says why, without the move's own line and without an Undo. On a phone and a tablet they sit just above the turn bar. On a desktop and in phone landscape (outside the draft) they sit at the foot of this player's own column, clear of the structure's bottom row, the cards a player can take.
- **Undo** is the game menu's "Undo last move" (greyed out, with the reason under it, while undo is not possible now), the top bar's arrow, the U key and Ctrl+Z (Cmd+Z on a Mac), in hot-seat and bot rooms only (the keys do nothing in a text field or while a sheet, a dialog or a dismiss layer is open: `game/undo-keys.ts`); online rooms have no undo. The bot and hot-seat sheets have an "Allow undo" switch (on by default): the game is created with it (`allowUndo` in `create`), the server fixes it for the game's life and reports it as `room.allowUndo`, and a game created with it off shows no undo anywhere (menu, top bar, keyboard, pass-device screen). The game menu's Hints sheet shows the setting read-only. The switch is remembered per mode on this device (`session/undo-default.svelte.ts`, `ajayeb:allowUndo`), next to the hints' local default, and the Session's create reads it. In a bot room undo also takes back the bot's reply (the server does that); pressed while a bot answer is held for its dwell, the answer shows first and is then taken back. A successful undo in a bot room shows “Undid your last move.” in a short toast; its polite live region announces the same confirmation once.
- **Against the bot.** The bot's seat is named by its persona (`names.ts`: Apprentice for easy, Scholar for normal, Master for hard) wherever a seat name shows. While it thinks, the turn bar reads "<persona> is thinking" and its strip or panel shows `hud/ThinkingDots.svelte`, which stands still with Animation off. During the Presenter's preview the slot it takes, or the draft offer it picks, carries `data-bot-pick` and a ring in its crest colour: `botPick` in `card-actions.ts` finds it from the answer's events, and the game screen passes it down as a prop (`botPick` on CardStructure, which hands `StructureSlot` its own `botPick`, and on Draft), so the ring is ordinary markup, not an attribute set on the DOM from outside.
- **The military track** has the capital of the seat at the bottom (or on the left) at its left end: a player at the Moon sees it mirrored, with the pawn, the zones and the looting tokens following (`ui/track.ts`). Spectators and the Sun see it as the view states it. It is drawn as its 19 spaces (`view/track-cells.ts`): zones shaded deeper toward each capital with a line at every boundary, each looting token on its own space (3 or 6) showing the coins it takes, and each zone's points on a laurel tablet under the bar. The desktop adds a legend line.
- **The opponent move summary** (`game/MoveSummary.svelte`, one `game/MoveSummaryLine.svelte` per line, `view/move-summary.ts`): when a live frame hands the turn back after the other side's moves, a popup lists them in order, consolidated (a bot's reply, both moves of an extra turn and the choices inside a turn are one summary): the card and how it was taken, the coins paid and the trade part, other coin changes, the pawn, looting, a science pair, the token taken, a wonder and what it destroyed or revived, an age change. It opens once the Presenter shows that frame, including history a join or resync brings when its opponent moves were not seen. Undo and the wonder draft never open it (`summaryTrigger`). It is a DismissLayer: any tap closes it and is swallowed, and Escape closes it. It sits over the structure's top on a phone and over the viewer's own column on wide screens and in phone landscape. Settings' "Show opponent move in detail" (`showOpponentMove` in `ajayeb:settings`, on by default) stops it opening by itself; the top bar's eye (`data-control="move-summary"`, next to the log, shown once the other side has moved) always opens the latest one (`latestSummary`). Below 26rem the top bar drops its settings gear to make room (Settings stays in the game menu). The panel ends with an empty `data-summary-review` slot for the move review line. The e2e base fixture turns the popup off; summary and tutorial flow specs turn it on. On reconnect, reload or waking a hidden page, unseen opponent moves open it with “While you were away”. `ui/seen-moves.ts` remembers the last visibly presented history ply per room, mode and seat in `ajayeb:seen-moves`, bounded to forty entries and tolerant of blocked storage. A hidden incoming frame never advances it. Dismissing a displayed summary records it immediately, so a rapid hide/wake cannot replay it. Undo clamps the marker to the shortened history, and the display setting still applies. The hot-seat pass screen already summarizes the move, so it replaces the automatic popup; the eye button still opens it manually.
- **The game menu** (the top bar's first button, every mode) holds Home, Settings and the log, and Forfeit while the game runs. Forfeit opens `game/ForfeitConfirm.svelte`, which names the winner (and, in hot-seat, the player to move, who is the one forfeiting); only its confirm button sends `resign:<seat>` (`Session.resign`). The game-over dialog then says who forfeited. Home leaves the room; the room stays on Home's Continue list until its game ends, and the hint under Home that says so is gone once the game is over.
- **Online rooms.**
  - While the room is in the lobby, the game screen shows `screens/Lobby.svelte`: the code in large type, the invite link with Copy link (and a toast) and Share (only where `navigator.share` exists), and a QR code drawn from `uqr`, which loads only when the lobby shows. The lobby turns into the draft when the friend's join arrives.
  - The other player's strip or panel shows `hud/PresenceDot.svelte`: a filled dot when connected, a dashed ring and the word "away" when not, so it reads in greyscale. A toast says when they join, leave or come back, and while they are away the turn bar's waiting text says so.
  - While this tab's own connection is down, the ConnectionPill (icon only in the top bar below desktop widths) and the turn bar say so, the board stays open for inspection, and every move button reads "Waiting for connection" and is disabled. The fresh state after the reconnect restores the board.
  - A spectator sees the board read-only, with "Watching" in the turn bar, a note in the card sheet and no actions. Players see the spectator count (`hud/SpectatorCount.svelte`) in the top bar.
  - Rematch on the game-over dialog asks for the rematch room and moves there. The other player sees "<name> wants a rematch" and a Join the rematch button; a spectator gets Watch the rematch.
- **Hot-seat** shows the pass-device screen between turns of different players when the setting is on (by default on touch screens), with the last move's summary and an undo for the previous player (only in a game that allows undo).
- **Draft, choices and game over.** `screens/Draft.svelte` fills the main area during the wonder draft. `choices/ChoiceHost.svelte` stays mounted through the play (it shows pending choices and the bar that says who starts a new age), except while the pass-device screen is up, since its modal panels would cover that screen. Its bars (`choices/PeekBar.svelte` with `inline`) sit in the flow just above the turn bar, so they cover neither the takeable cards nor the player's own strip; the who-starts bar also closes on the first tap on the structure. `screens/GameOver.svelte` is its own centred dialog once the game is over. They take `{view, canAct, onact}` and `{view, onrematch?, onhome}`.
- **Test contract.** Structure cards keep `data-card` and action buttons `data-act`. Further hooks for drivers: `data-control="wonder-step"`, `"wonder-build"`, `"wonder-pick-cancel"`, `"undo"`, `"log"`, `"settings"`, `"move-summary"` (the top bar's eye), `"open-city"`, `"menu"`, `"menu-home"`, `"menu-settings"`, `"menu-log"`, `"menu-undo"` (with `data-undo-reason` under it while greyed out), `"menu-forfeit"`, `"allow-undo"` (the new-game sheets' switch, in a `data-allow-undo` row), `"forfeit-confirm"`, `"forfeit-cancel"`, `"wonders"` (a strip's wonder button), `"wonder-list-back"`; `data-forfeit-confirm` on the confirm step; `data-wonder-list` (the seat) on the wonder list; `data-wonder` on wonder buttons and `data-buildable` on those that can be built now; `data-covered-cost` (`own` or `other`) on a covered card's cost lines; `data-military-danger` (the glow level) on a strip's danger shield; `data-marked` on pickable slots; `data-bot-pick` on the slot or draft offer a bot is about to take; `data-thinking` (the bot's seat) on the game screen and on the thinking seat's panel; `data-turn` (the TurnState kind) on the turn bar; `data-left-seat` and `data-mirrored` on the military track; `data-pass-device` on the pass screen; `data-control="replay-last-move"` in the log sheet (inside a `data-replay-tooltip` group, which carries the tooltip while it is disabled); `data-toast` on toasts; `data-move-summary` (the mover's seat, with `data-plies`) on the move summary and `data-summary-line` (the line's kind) on its lines; `data-setting="show-opponent-move"` on its Settings switch. Online: `data-lobby`, `data-room-code`, `data-invite-link`, `data-qr` and `data-lobby-seat` in the lobby, `data-control="copy-link"`, `"share-link"`, `"lobby-home"`; `data-presence` (`connected` or `away`) on presence dots and seat panels; `data-away` on the turn bar while the waited-for player is away; `data-spectators` on the spectator count; `data-watching` on the spectator's card-sheet note; `data-rematch` on the rematch button; `data-home-hint` on the menu's Home hint; `data-undo-setting` (`on` or `off`) on the Hints sheet's read-only undo setting; `data-name-prompt`, `data-name-input`, `data-control="name-submit"`; `data-online-sheet`, `data-control="online-create"`, `"online-join"`; `data-join-sheet`, `data-code-input`, `data-control="join-submit"`, `"home-join"`; `data-room-error` and `data-control="error-home"`.

The `/dev/gallery` page has a Game screen section that shows recorded states (draft, Age I, Age II, Age III, a pending choice, game over, and the online lobby, opponent-away and watching states) in frames of a phone and a desktop size. Its Online section shows the lobby (a fixed fake code and QR, also reconnecting), the name prompt, the online and join sheets, the room error, and the connection states of the pill, the presence dot and the turn bar.

## Hints on the board

The game's hints (docs/dev/decisions.md D23, the hints design) are drawn from the server's fields only: `SlotView.hints`, `View.hints`, `PlayerView.hints`, `WonderView.effect`, `Choice.outcome` and `PendingView.cardHints`. `src/lib/view/hints.ts` words the per-card hints and picks each card's pip, `view/outcome.ts` the decider's outcome lines, ghosts and warnings, and `view/board-hints.ts` the board-level hints (the science tracker, the military track, the wonders, the progress tokens, the age chip and the age interstitial). `view/threats.ts` turns the board hints into the strips' glow levels. Every hint follows the families this screen shows (`visibleFamilies`: the game's settings minus the local hide), and marks on the board (pips, ghosts, glow upgrades, the hourglass, the ready mark, the Law laurel) also follow the local hide's board switch. Nothing is shown once the game is over.

The pip vocabulary. Shape carries the meaning, fill the side, so colour is never the only cue:

- **Shapes.** A crown is a win (`win`). The progress-token frame with a science symbol inside is a pair (`pair`). The coin-loss glyph is looting (`loot`). The hourglass is the race for the last wonder (`hourglass`). A check in a ring is a wonder its owner could build at today's prices (`ready`). A laurel ring around the Law medallion says Law would be a seat's sixth symbol (`law`).
- **Fills.** Solid is this screen's own fact (gold; the mover's crest on a hot-seat device). Outlined (or dashed) in the opponent's crest colour is the opponent's fact, a deny target. A light crest tint is a spectator's view of either seat.
- **One pip per card.** A card shows the highest pip of the priority table in `view/hints.ts` (own win, opponent win, own pair, opponent pair, own loot, opponent loot) on its top-end corner, and a hairline dot beside it when it carries another hint. The pip's tooltip lists every hint on the card.
- **Science slots.** The tracker's seven slots show where a seat stands on each symbol: paired (the ring), live (one card, and a dot under it: the other may still come), owned (one card, no dot), open (a dotted outline: none yet, and a card may still come) and dead (a hairline strike: none can come). Each slot's tooltip names its two cards and where they are.
- **Glows.** A strip or panel glows in four levels: none, calm (a faint hairline: close, but it can no longer happen), soft (the warning) and strong (a thicker ring: a win with one action exists now).
- **The track.** A crown under each capital says that reaching it wins the game at once, apart from the zone tablets, whose tooltips say that only the player ahead scores them at the end. With the military hints, a capital shows the shields the opponent still needs at 5 or fewer, and its tooltip says whether the opponent can still gather them.

Move outcome lines label the server's score change as total VP, with coin points included in the tooltip and screen-reader text. The phone form keeps the total VP label. Zero-coin looting contributes no pip or loss line. Progress-token savings distinguish Masonry's blue cards from Architecture's wonders. Pawn log lines use player display names, with a crest fallback for unnamed seats.

## Tooltips

Tooltips never use the native `title` attribute. Give an element one with the `tooltip` attachment from `src/lib/ui/tooltip.svelte.ts`:

```svelte
<span {@attach tooltip({ text: t('board.resource.chip', { resource, count, coins: t('coins.count', { count: price }) }) })}>
```

Pass `undefined` instead of the content for no tooltip (a conditional one). The content has `text` (already through `t()`, short), an optional `diagram` snippet (a small concept picture whose labels are translatable text beside the SVG, never baked into it), an optional `stack` of linked previews, optional `lines` (short status lines under the text, such as the hints a tooltip adds), an optional `rulesId` (a `RuleSectionId`: the rules reference section its "More in Rules" link opens), and an optional `actionable` override for the touch model, and `avoidAnchor` for a whole-card summary that must use a free column before covering its card.

- **The layer.** `components/shell/TooltipLayer.svelte` is mounted once, in the root layout. It installs the gestures (`installTooltipGestures`) and draws the one open tooltip in a manual popover, so it shows above an open sheet too. The bubble (`TooltipBubble.svelte`) and the stack (`TooltipStack.svelte`) are plain leaf components that the gallery also renders standalone.
- **Fine pointer.** A hover shows the tooltip after 450 ms; moving to the next anchor within 300 ms of a tooltip closing shows the next one at once. Keyboard focus (focus-visible only) shows it at once. Escape closes it, and only it: the sheet beneath stays open. A mouse click acts as usual and closes any open tooltip, a keyboard focus one included, so a tooltip never lingers over the menu or sheet the click opened and takes its Escape.
- **Touch (model B).** A tap on an element with no action shows its tooltip. An element is actionable when it or an ancestor is a button, a link, a form control, a `summary`, a `label`, an element with an interactive role or a `data-act` (`ACTIONABLE_SELECTOR` in `ui/tooltip-gesture.ts`), and is not disabled. An actionable element keeps its tap and shows its tooltip on a 500 ms long-press, whose release is swallowed so it never acts. A finger that moves more than 10 px cancels the press, so a long-press never fights scrolling, and the browser's own long-press menu and callout are suppressed on anchors. Any tap while a tooltip is open closes it and is swallowed: neither the press nor its click reaches the page.
- **The "More in Rules" link.** A tooltip with a `rulesId` shows a link under its text that closes the tooltip and opens the rules overlay at that section (`openRules`). Every concept tooltip carries one (a cost rule, a chain, a zone of the track, a science symbol, a guild, a wonder, a token); a tooltip whose sentence says it all (a cost pip, production, plain points or coins) does not. Only the link row takes pointer events; the bubble body always lets the pointer through. With a fine pointer, the mouse can move from the anchor to the link (the hide delay grows to 300 ms for a linked bubble, `HOVER_HIDE_LINK_MS`), a press on the link leaves it open, and the link's click closes it; after any click, hovering shows no new tooltip until the mouse moves 4 px, so the click never pops one up under a resting pointer. On touch, a tap on the link is the one tap that is not swallowed while a tooltip is open: it acts (`downAction` in `ui/tooltip-gesture.ts`); a tap anywhere else, the bubble's own text included, closes the tooltip as before. Escape still closes it. The link is not a tab stop (`tabindex="-1"`, like the tooltip itself): keyboard users reach the same sections through the game menu's Rules entry and the rules overlay's own section list.
- **Micro-element tooltips.** `src/lib/view/tips.ts` words the board's smallest elements from catalog data and the numbers the server sent, and decides nothing: each cost pip (and how the payment in view covers that resource), the "+n" of a cut cost row, each effect glyph, the affordability badge (a trade lists what it buys and at what price), a face-down back, the coin and point tallies, and an owned guild's points. The optional next-point, winner-on-points and guild-point lines follow the scoring hint family. Linked chain details use `ui/chain-links.ts` and are independent of hint settings.
- **Whole-card summaries.** Every `CardFace` tier attaches its summary to the face, with no extra per-card DOM. The open bubble mounts once. The art, frame and name show the card's name, category and age, one line per printed effect, its costs, chain links and city builder. Nested pips, glyphs and chips keep their own tooltips. Occupied structure slots are enabled inspection buttons even when covered or face down: a short tap opens their sheet, and a long-press shows the innermost tooltip without opening it. Legality still comes from server choices and `data-accessible`. Face-up structure cards use `View.cardTooltips` for both seats' current totals, including covered cards and unaffordable quotes. A seated viewer sees You and the named rival; hot-seat and spectator views name both seats. City/discard/gallery cards show printed costs, except a legal Mausoleum rebuild uses the explicit free `revive` choice payment. Actual construct/revive payments take priority over hypothetical public quotes, and are passed as display props; no action key is parsed to infer a cost. These are public quotes, not a promise that a card is legal to take. The server indexes only identities already in the redacted structure, cities, discard or visible tucked cards; compact cost summaries omit production-source ids and full breakdowns. The printed catalog supplies effects and chain names.
- **Linked chain details.** Chain chips show the linked building's kind, age and effects. With public snapshot data, they also show whereabouts, and outgoing links show the server's current cost without the chain for the link holder. A city uses its actual owner; a structure card uses the planning seat. These facts are independent of counting hints. Reverse links, including the chain affordability badge, preview the granting building without a price. Live details use compact text instead of a duplicate image stack and diagram. Components receive the displayed snapshot through plain props, and the linked text mounts only when the tooltip opens.
- **Draft cards and wonders.** The draft uses `WonderTile`, so its art/frame also carries a whole-item summary, as do city rows, sheets and gallery tiles. It names the wonder kind without an age, reuses each printed effect phrase, shows the owner's server quote when available or the printed cost, and includes visible taken/built/removed state. A wonder belongs to one seat, so it has no rival build quote. Inner glyphs and hint marks still win.
- **City cards.** Each city colour band is an accessible disclosure. Opening it mounts that colour's cards with the builder's name; closing it removes them. This keeps the initial board DOM small while making every city card inspectable. Passive city cards and standalone gallery/sheet cards have a keyboard stop; an enclosing structure/pick button uses the full-card summary as its description without adding a second stop.
- **Face-down cards.** The back tooltip states only its age or guild back and that taking the cards covering it turns it face up. It does not list candidates, values or costs.
- **Compact diagrams.** The rules reference's diagrams (`TradeDiagram`, `ScienceDiagram`, `MilitaryDiagram` in `components/rules/`) take a `compact` prop, at most about 220 by 120 px, for a tooltip's `diagram` snippet: the trade badge shows the trade rule (headed "For example:", so its numbers never read as the game's), the science counter the seven symbols, and the track's zones and looting tokens the zones.
- **Innermost wins.** The anchor is the innermost registered element under the pointer or finger: a chain chip inside a card slot shows the chip's tooltip, and the rest of the slot the slot's own. One tooltip shows at a time.
- **Stacks.** A stack is a second panel of up to two linked previews, joined to the bubble by a short gold connector: beside the bubble when both fit side by side (from 640 px wide, and on any screen too short to stack them, such as a phone in landscape), otherwise on the bubble's far side from the anchor, so the bubble and its arrow stay next to the anchor. Stacked that way, the two move as one: where the group does not fit beside the anchor the bubble gives way, so the bubble and the stack never overlap. A `card` item draws a real full-tier `CardFace` at 140 px; a `custom` item renders the caller's snippet. One tap closes the bubble and its stack together. Catalog-only chain chips use it (`ui/chain-links.ts`): a chain-out chip says which card it makes free and stacks that card, and a chain-in chip says which card provides the symbol and stacks that card.
- **Where a stack fits next** (for the content slices): the "free through <card>" line of the card sheet's cost breakdown; a wonder row's "Built with <card>" (the card spent on it); a resource chip whose trade price a card fixes at 1 coin (that card); a science symbol in the tracker (the city cards that show it, so a pair is visible); a guild's or commercial card's "per card" effect (the counted cards, as a custom snippet); and the log's and the opponent move summary's entries (the card built or discarded).
- **Placement.** `ui/tooltip-place.ts` is pure, unit-tested math: above the anchor by preference, flipped below when it does not fit, shifted sideways so it never leaves the viewport less the safe-area insets (measured by a probe element), with the arrow pointing at the anchor. Whole-card summaries and nested chain details use the entire face as their exclusion box, while gestures and accessibility keep the original anchor. If neither above nor below fits, the layer can reflow into a free side column; lateral bubbles hide the existing arrow. The boxes are placed in viewport pixels in a `dir="ltr"` overlay, while their text follows the page's direction. A scroll carries the tooltip with its anchor, and closes it once the anchor leaves the viewport; a resize closes it.
- **Motion.** The tooltip fades in over `--dur-fast`, which follows the game's Animation setting; with Animation off it appears at once.
- **Accessibility.** The bubble has `role="tooltip"` and the id `ajayeb-tooltip`; a focusable anchor gets `aria-describedby` pointing at it while it shows. Micro-elements inside a focusable card (its chips and glyphs) are not focusable themselves: the card's own accessible name describes them, so there is no tab stop per symbol.
- **The dismiss layer.** `components/shell/DismissLayer.svelte` is a floating panel (a manual popover, centred by default; pass position classes to move it) with the same rule: any tap closes it and is swallowed, and Escape closes it. With `keepInside`, taps inside the panel reach their targets (a coach mark's Next button) and only taps outside close it. As a dialog (the default role) it takes the keyboard focus when it opens, keeps Tab and Shift+Tab inside, and gives the focus back to the element that had it (the button that opened it) when it closes (`trapFocus` in `ui/dismiss.ts`). It is made for the opponent move summary, the first-time tips and the tutorial's completion card (the coach marks are not one: they must let the tap they ask for through). `installDismiss` and `swallowClick` in `ui/dismiss.ts` are the behaviour on its own, for any other overlay. First-time tips opt into `passTouchActions`: a touch press on an enabled card or action dismisses the tip and reaches that target. They use a nonmodal note role and do not take keyboard focus. Other outside taps still dismiss and are swallowed. Tooltips and move summaries keep the any-tap-swallowed rule.
- **Gallery and tests.** `/dev/gallery/tooltips` (linked from the top of `/dev/gallery`) shows every variant: plain text, parameters, a diagram, the stacked chain chips, a chip inside an actionable card, a button, the bubble and stack standalone, and the dismiss layer. `?show=<id>` opens the tooltip of the element marked `data-tip-demo="<id>"` for screenshots, and `?edges` adds stacked chain chips at the viewport's corners. `e2e/specs/tooltips.spec.ts` covers hover, focus, Escape and innermost resolution on the desktop project, and tap, long-press and the swallowed tap on the mobile project, and the "More in Rules" link on both (it opens the rules at its section and the game stays live; a bubble without a link lets the pointer through). `e2e/specs/tooltip-coverage.spec.ts` (both projects) opens one seeded hot-seat game at the wonder draft, a fresh Age I, a fresh Age III with a face-down guild and the result screen, and fails on any visible svg, img or `[role="img"]` element and any icon-only button of the game screen that has neither a tooltip anchor (on itself or an ancestor, or for a button a descendant filling most of it) nor a visible text label beside it. Its `ALLOW` list (at most 10 entries, each with its reason) holds only decorative paintings and the result screen's crests; a new glyph without a tooltip fails it. Test hooks: `data-tooltip` on every registered anchor, `data-tooltip-layer`, `data-tooltip-bubble` (with `data-side`), `data-tooltip-stack`, `data-card-preview` on a stacked card, `data-chain` and `data-chain-direction` on chain chips, `data-tooltip-rules` (the section id) on the link, `data-tooltip-lines` on the status lines, `data-cost-pip` (the resource) and `data-cost-more` in a cost row, `data-zone-tip` on the track's zone hit areas, `data-city-band` on a city panel's bands, and `data-dismiss-layer`. The gallery's board micro-elements section has `data-tip-demo` ids `pip`, `glyph`, `badge-trade`, `back`, `tally`, `chain-status`, `science` and `track-zone`.

## The tutorial

The guided first game (D25; the tutorial design of M10) is a server room like any other `ai` room. The server derives, for every frame, which lessons to show and the one action key the guided turn asks for (`State.tutorial`: the status `guided`, `free` or `complete`, the lessons, the action; docs/architecture.md, "Tutorial rooms"). The client decides nothing about the rules: it words those ids and points at the elements they name. All of it lives in `src/lib/tutorial/` (pure modules, unit-tested) and `src/lib/components/tutorial/`.

The tutorial keeps its frozen Great Lighthouse move: its flexible raw-material
production helps pay for later builds, which the wonder lesson now explains.
Temple of Artemis would grant another turn and change subsequent scripted bot
replies, so teaching it requires a newly named script (D25).

- **The step machine.** `tutorial/steps.ts` turns the frame's tutorial object, the info lessons acknowledged on this tab and a snapshot of the UI (which sheet is open, on which card, at which step) into the one coach step to show now, or none. Info lessons come first and end with Next. The action lesson then becomes, by the key's verb, a tap step on the card or tile to open, a tap step on "Build a wonder" in the card sheet, or an act step on the move button itself; a sheet open on another card gives a note naming the expected one. The acknowledgements are kept per tab in `sessionStorage` (`ajayeb:tutorial-acks`, keyed by room, ply and lesson), so a reload mid-lesson shows the same step, and an undo forgets them from the ply it went back to.
- **The coach mark and the note.** On the board the step shows as a coach mark (`CoachMark.svelte`), a bubble in a manual popover with an arrow at the target. It is not modal and not a `DismissLayer`: it swallows no tap and takes the pointer only on itself, so a tap on the target, or on any other card, works as usual. It carries the lesson's number and Next or "Play on my own". Inside a sheet it shows as a note (`CoachNote.svelte`) in the sheet itself, because a native modal `<dialog>` makes the rest of the page inert and a bubble outside it could not be pressed. `CoachLayer.svelte` decides which one shows and hides the bubble while any modal is open.
- **Placement.** `tutorial/place.ts` is the tooltip layer's placement with two more rules: the bubble never overlaps an element target and covers at most 40% of a region target (the structure, the draft offer, the wonder list); when neither side has room it is pinned to the far edge with no arrow. Information lessons reserve the measured top bar so the game title stays visible. A pinned region bubble can shift sideways to preserve the region cover limit. Action prompts use the full viewport to keep their target clear. On a short screen the bubble is wider and its text scrolls, so it fits a phone held sideways.
- **The ring.** The target gets the attribute `data-coach-target` (with `data-coach-region` on a region), on exactly one element at a time; a global style draws the ring. The layer scrolls a target in a scroller into view once, and again when an image loads under it within two seconds (a late card image can push it off screen). The target gets `aria-describedby` pointing at the step's text, the focus moves to Next or the target, and a polite live region reads each new step once.
- **Anchors.** `tutorial/anchors.ts` finds a step's target by selector, the first visible match winning (some anchors exist twice, such as the full and the compact military track). Scroll containers leave room around the target for its full coach ring. New `data-tut` attributes exist only where no stable one did: `structure`, `turn-bar`, `home`, `away`, `track`, `tokens`, `wonders`, `draft-offer` and `age`. The rest reuse the e2e contract (`data-card`, `data-act`, `data-pick` and so on). Like those, they are a test contract: do not rename or remove them.
- **The rails.** `tutorial/gate.ts` disables, during a guided turn, every move button whose key is not the guided one, with one short reason per sheet (`data-tutorial-reason`, worded by verb in `tutorial/text.ts`) and the locked button wrapped in `data-tutorial-locked`. It is a display rule only: the server accepts any legal key, and a different one simply leaves the script. Undo, the menus, forfeit, the sheets and the tooltips are never gated. "Play on my own" appears only while the server status is `guided` and pauses the tutorial for that room (the rails and the bubbles go; the game menu's "Resume tutorial" brings them back, and says so with the `leftPath` lesson when the game left the path meanwhile). Leaving the path shows the `leftPath` lesson once, and the game goes on as a normal game.
- **Device state.** The first-time tips' store (`ui/tips.svelte.ts`, `localStorage` `ajayeb:tips`) also keeps the tutorial's: Home's first-launch offer (`new` or `declined`), whether the device finished it once, and the tutorial rooms paused or completed. A separate `roomOrder` list records oldest to newest, so all-digit room codes keep their recency. Old entries without a list migrate using the saved object’s enumeration order; any earlier numeric-key insertion order cannot be recovered. Settings' "Show the tutorial offer again" (`data-control="tutorial-reset"`) makes the offer new again.
- **Home.** On a device with no saved rooms and the offer new, Home shows an inline panel (`TutorialOffer.svelte`: Play the tutorial or No thanks), and a quiet "Learn to play" row (`data-control="home-tutorial"`) always sits under the mode buttons ("play it again" once the device finished it); the vs-AI sheet links to it too. A tutorial room in Continue is marked as one.
- **The end.** When Age II begins the status is `complete`, and once no modal is open the completion card (`TutorialDone.svelte`) shows over the board: Keep playing (the game goes on against the bot; a tap outside does the same), New game (Home with the vs-AI sheet open, through `?play=ai`) and Home. It shows once per room.
- **The concept tips.** Three first-time tips explain a concept rather than a mark: the pawn off centre (`track`), the seat's first science symbol (`science`) and a new age in play (`newAge`, which also says who chose its starter). They show for every player, in or out of a tutorial; the tutorial's lessons mark the ones they teach seen, and no tip shows while a guided step is up or beside the completion card, whose dismiss layer would swallow the first tap on it. There is no tip at the starter choice itself: that choice is a modal dialog, so a tip outside it would be inert. The new-age tip is due only at the start of Age II, while at most one structure card has been taken (the bot may start), so a late resume never replays it.
- **Names.** Hint and outcome lines use the same seat display names as the player strips: translated bot personas, numbered human names and crest names only for unnamed seats.
- **Strings.** Every tutorial string is in `i18n/en/tutorial.ts` (and `fa/tutorial.ts`), including Home's and Settings' tutorial strings. A lesson's `{resource}` is read from the printed catalog card, never from the game.
- **Test hooks.** `data-coach-step` (the step id) and `data-coach-kind` (`info`, `tap`, `act` or `note`) on the bubble and the note, `data-coach-target` and `data-coach-region` on the target, `data-coach` on the bubble, with `data-coach-turn` (the lesson's number), `data-coach-placement` (`above`, `below` or `pinned`), `data-coach-next` and `data-coach-pause` (Play on my own), `data-coach-note` on the note, `data-tutorial-locked` and `data-tutorial-reason` on the rails, `data-tutorial-offer` with `data-control="tutorial-start"` and `"tutorial-decline"`, `data-tutorial-done` with `data-control="tutorial-keep"`, `"tutorial-new"` and `"tutorial-home"`, and `data-tutorial-replay` on Home's row once the device finished it. The test hook (`session/test-hook.ts`) adds `tutorial()` (the frame's tutorial object) and `coach()` (the step on screen). The gallery's Tutorial section (`dev/gallery/Tutorial.svelte`) renders the bubble at every placement, the note, the offer and the completion card.

## The rules reference

The rules of the base game, in our own words, live in two places that work together:

- `src/lib/i18n/en/rules.ts` holds the text, one key per paragraph, list item or definition. It is written from `docs/rules/` (never from the rulebook; see `docs/legal.md`). Card, wonder and token names are never written there: a `{placeholder}` names them, filled from the existing name keys.
- `src/lib/components/rules/sections.ts` arranges those keys into sections, each with a stable id: `goal`, `setup`, `turn`, `costs`, `military`, `science`, `wonders`, `tokens`, `guilds`, `age-end`, `scoring` and `glossary`. Tooltips and hints link to these ids, so add new ids rather than renaming one. `sections.test.ts` checks that the ids are unique, that every key exists and that every placeholder is filled.

They show in two ways:

- **The page `/rules`**, linked from the Home footer (`data-control="home-rules"`). It has a table of contents, and each section is a deep link such as `/rules#military`.
- **The in-game overlay**, opened by the game menu's Rules item (`data-control="menu-rules"`) without leaving the game. With room for two columns (`split`) it is a side panel over the opponent's column, so the board stays visible and usable; on a phone it is a bottom sheet (`shell/Sheet.svelte`, swipe down to close). Both have the contents as a row of chips and Close (`data-control="rules-close"`); Escape closes them too.

Any component can open the overlay at a section with `openRules('military')` from `components/rules/rules-overlay.svelte.ts` (no section opens it at the top, or where the reader left it). The first call loads the overlay in its own chunk and mounts it once at the end of `<body>`, so no screen has to place it, and it closes itself when the page changes. The diagrams (`MilitaryDiagram`, `TradeDiagram`, `ScienceDiagram`, and the concept diagrams `ChainDiagram`, `DiscardDiagram`, `SeventhWonderDiagram`, `GuildDiagram` and `StarterDiagram`) are built from the board's own components and the icon sprite, with every label as translatable text. The five concept diagrams share `DiagramFrame` and take a `compact` prop: compact drops the frame and the visible caption (it stays for screen readers) and fits a tooltip bubble of about 220 by 120 CSS px, for use as a tooltip's `diagram` snippet (`{#snippet d()}<ChainDiagram compact />{/snippet}`); the full form sits in its rules section. Test hooks: `data-rules-page` on the page, `data-rules-overlay` (`drawer` or `sheet`) on the overlay, `data-rules-panel` on its body, `data-rules-section` on each section, `data-rules-toc-item` on each contents entry and `data-rules-diagram` on each diagram. `/dev/gallery` has a rules section under Screens with the diagrams, the panel at two widths, and buttons that call `openRules()`.

## Sound and haptics

`src/lib/fx/` plays short cues when a frame's events arrive. `sfx.ts` plays decoded CC0 AAC files from a small cache, fetching and decoding each cue once after the first audio-unlocking gesture. Before a file loads or if it fails, a WebAudio synth plays immediately instead. The 17-file inventory includes the seven original cues and wonder, token, loot, ageStart, defeat, yourTurn, destroy, rebuild, libraryDraw and extraTurn; the new names can be auditioned in the gallery. [Sound preparation](../docs/art/sound.md) records the pipeline and licensing. `cues.ts` is the pure, unit-tested mapper from a frame's events to cues and a vibration pattern. The Presenter calls `playFrameFx` once per shown frame. A frame that carries a `history` (a join, a resync, the frames after an undo) plays nothing, so a move already heard is never heard again (`cuePrev`).

- Only live events play. The first snapshot of a room, another room's frame, and a frame whose version does not move forward (an undo, a resync) are silent.
- Each cue kind plays at most once per frame, 90 ms apart, in the order of its first event. When the frame animates, the cues are retimed to their animations (see Animations below).
- Settings: Show opponent move in detail (on by default; see the game screen's move summary). Sound (off by default) with a Quiet, Medium or Loud step, and Vibration (on by default, shown only on a touch device where `navigator.vibrate` exists, so never on desktop Chrome: `screens/vibration.ts`). Sound does not follow the Animation setting. The AudioContext starts only inside a user gesture: the Sound switch itself, or any later pointer or key press.
- Haptics: 8 ms when a card or wonder is taken, a short pattern when the pawn moves, a longer one for looting. When the frame animates, `haptics.ts` waits for the step a pattern belongs to (`hapticOffset` in `fx/anim/plan.ts`, passed explicitly from the timeline for that frame): the take as its card lands, the pawn's pattern with its first step, the looting's as the first token flips. A newer frame, finish, hurry, undo, leaving the room or switching Haptics off cancels a vibration still waiting. The timeout also checks the setting before it plays. Animation off keeps one immediate vibration.
- Test hook: `window.__ajayebFx.cues()` and `.haptics()` list what would have played (a cue only while Sound is on, a vibration only while Vibration is on), and `.clear()` empties both. Every cue carries its frame version and a `replay` boolean. Visual replays use the same recording and Sound gate. `e2e/specs/sound.spec.ts` reads it.
- `/dev/gallery` has a sound board under Screens, with file and synth-fallback buttons side by side for every cue. Files use generated content-hashed URLs under `/sfx/`, never the install precache, and enter a bounded runtime cache only after the audio-unlocking gesture. The three volume steps are unchanged; slide and yourTurn have lower relative gain, and at most three voices overlap.

## Animations

`src/lib/fx/anim/` animates each frame's moves and events, driven only by the server's events (UX design section 5; D21: only the game's own Animation setting counts, never the OS's reduced-motion preference). The state is instant and authoritative; animations are visual only.

- **The planner** (`plan.ts`, pure): a frame's live events and the views before and after become a timeline of steps with starts and lengths at normal speed. Live events only, as for the sound cues: nothing on a room's first frame, a resync, an undo or a frame with a history. `speed.ts` scales every time of a step by the setting (`scaleMs`); Off gives the empty timeline. The steps:
  - `take`: a build, a discard or a wonder's card leaves its slot (320 ms);
  - `rebuild`: the Mausoleum's card rises from the discard pile's choice to the builder's city (420 ms);
  - `destroy`: a destroyed card leaves the victim's city, thrown out of the board (560 ms);
  - `token`: a progress token flies from the board's row, or from the Great Library's offer, to the taker's token row (420 ms);
  - `draft`: a drafted wonder's tile flies from the offer to the picker's row, the round's last wonder after it (420 ms, 160 ms apart);
  - `flip`: each reveal, after the take lands (350 ms, 60 ms apart);
  - `coins`: a seat whose coins changed, a float and a counter tween from the views' own numbers;
  - `pawn`: 150 ms per cell;
  - `loot`: a looting token flips to a blank coin and fades as the pawn reaches its cell, and the victim's coins drop with a loss float (the counter tween chains after the coins step's);
  - `glow`: a science pair, the symbol glowing in the taker's tracker (900 ms);
  - `draw`: the Great Library deals its three tokens one by one: to the drawer face up, into its choice; to everyone else as backs (the token frame alone) fanned over the board. A step names a token only when the viewer's own event does, so a viewer who may not see the offer gets nothing that names it;
  - `deal`: a new age, the old structure fading out and the new one dealt card by card from a deck above it, top row first (30 ms apart, 240 ms each, after a 120 ms lead). When the age opens on the starter choice (Ages II and III), whose dialog covers the board, the deal waits for the frame that answers it, as the dialog closes, and has no fade. Each real slot stays hidden until its card lands, so no card can be clicked while it cannot be seen; the deal's tail does not hold input;
  - `victory`: after everything else of the frame, a banner naming the victory kind, tinted by it (cinnabar for military, green for science, gold for civilian, neutral for a shared result or a forfeit), with 12 particles, over the result screen (1700 ms). It never takes a tap.
- **The hooks**: `session/app.svelte.ts` gives the app's Presenter an `AnimRunner` (`runner.ts`) as its `capture`, `play` and `finish` hooks. `capture` finishes whatever still runs, plans the frame and reads the old DOM (copies of what leaves, the structure an age replaces, the looting tokens the pawn will take); `play` reads the new DOM once, then starts every animation. A frame with others queued behind it is not animated.
- **Anchors**: the runner finds its elements by attributes, inside `.game-screen` and a seat's `.seat-panel[data-seat]`: the taken card by `data-card` in `.card-structure`, a revealed slot by `data-slot`, a city colour by `data-fx-band` (CityBand), the city on a phone by `data-fx-city` (the strip's name button), a wonder by `data-fx-wonder` (its row) or `data-fx-wonders` (the strip's wonder button), the coins by `data-tally="coins"` and its number `data-fx-count`, the pawn by `data-fx-pawn` (both tracks), a looting spot by `data-loot-at`, a progress token by `data-fx-token` (ProgressToken, wherever it is drawn) and a seat's token row by `data-fx-tokens`, a science symbol by `data-fx-science` (the tracker's slot) or `data-fx-science-pill` (the phone's pill), a card of the discard pile's or a city's choice grid by `data-fx-pile-card` (CardPickGrid), a draft offer by `data-wonder-offer` and a picker's row by `data-draft-picks` with its chips' `data-picked`. A discard has no pile on the board, so it flies into the discarder's coins; a destroyed card is thrown out of the board for the same reason (it would fly to a `data-fx-discard` pile, should one appear).
- **FxLayer** (`components/shell/FxLayer.svelte`, mounted by the game screen): a fixed, unclickable overlay above the board and below the pass-device screen, toasts, sheets and tooltips. Flying cards, flips and floats are clones drawn there, stripped of `data-card`, `data-act`, `data-slot`, `data-pick` and ids, so no test or driver can find or click one. Beside it is its top part (`.fx-top`), a manual popover the runner shows only while it draws over a dialog (the Great Library's tokens dealt into the drawer's choice, the victory banner over the result screen, a pair's glow when the dialog leaves the symbol in view), as unclickable as the rest. A destination inside a dialog that is still sliding in is aimed at where it comes to rest (`settled` in `dom.ts`). A destination that is new (a colour's first card, a token, a drafted wonder's chip, a dealt slot) carries `data-fx-hidden` (visibility hidden, its box kept, so nothing moves) until its flight lands; one that was already there gets a small landing pulse instead. A counter tween (`counter.ts`) writes the old number into the counter's text and puts the server's number back the moment it ends or is finished.
- **The blocking budget**: the play hook resolves as the take settles, 240 ms after the swap at normal speed (the flight's last 80 ms, when it only lands, do not hold input; never more than 350 ms), so `presenter.idle` and the move buttons are back within 450 ms even when the swap's own render is slow. The hold counts from the swap. Only the frame's lead (a take, a rebuild, a destroy, a token or a draft pick) holds; flips, floats, the pawn, the looting, the glow, the deal and the banner play on without holding input.
- **Interrupts**: a new frame (from `capture`), `presenter.hurry()` and `presenter.clear()` finish every running animation at once (`animation.finish()` and each step's cleanup), so the screen never shows two frames at once. The bookkeeping is `runs.ts`, unit-tested with stand-in animations.
- **Sound**: when a frame animates, its cues sound with their steps (`speed.ts` `retimeCues`): the slide when the card lands (or as a destroyed card goes), a flip with the first flip, a coin with its float, the drum with the first looting (else the pawn's first step), the chime with the glow (else a token's landing), the fanfare with the banner, the draft tick as the first tile lands. With Animation off they keep their 90 ms spacing.
- **Replay last move** (`replay.svelte.ts`, the log sheet's control): the runner keeps the last move it animated, its normal-speed plan and copies of what it read from the old DOM, and offers it; a frame that plays nothing (Animation off, a resync, an undo) withdraws the offer. The control closes the sheet and the runner plays the move again on the board as it is now, at the current speed, with its sounds while Sound is on. It changes no state and sends nothing. It is disabled, with a tooltip saying why, while Animation is off or before any move has animated. A replay is not a frame: `__ajayebFx.frames()` does not list it, but `.anims()` does.
- **Test hook**: `window.__ajayebFx.frames()` lists each frame the runner was handed (`version`, `swapAt`, `releasedAt`, `steps`), and `.anims()` each animation (`version`, `kind`, `startAt` when it really started, `endAt`, `interrupted`); `.clear()` empties them with the cues. `e2e/specs/animation.spec.ts` reads them.
- **Turning animation on in a spec**: the base fixture forces Animation off once per tab. `e2e/fixtures/anim.ts` `useSettings(page, speed)` loads one page so that override has run, then writes the speed it wants; later loads in the tab keep it.

## Styling

- Tailwind's default colour palette is switched off. Use the semantic utilities, such as `bg-table`, `bg-panel`, `text-fg`, `text-fg-muted`, `border-rule`, `bg-accent` and `text-on-accent`, so every colour follows the theme. The palette and game colours are there too (`bg-card-red`, `text-sun-ink`, `bg-res-wood` and so on). The resource colours come in two kinds: `bg-res-wood` and the like are the resource tile fills, and `text-res-wood-ink`, `text-res-clay-ink`, `text-res-stone-ink`, `text-res-glass-ink` and `text-res-papyrus-ink` are the theme-aware inks for a resource glyph drawn straight on a page surface (paper, panel, parchment, or the night panels in dark mode). The inks keep 3:1 or more against those surfaces; the fills do not (papyrus and glass vanish on paper, wood on the night panels). A glyph on a resource tile or a card uses the card ink.
- The card colours come in the same two kinds, plus a third. `bg-card-brown` to `bg-card-purple` are the band fills. `text-card-brown-ink`, `text-card-grey-ink`, `text-card-blue-ink`, `text-card-green-ink`, `text-card-yellow-ink`, `text-card-red-ink` and `text-card-purple-ink` are the theme-aware inks for a category glyph (or any glyph inked by its card colour) on a page surface, such as the city chips, the score table and the discard filter. On a card face, which stays paper in both themes, use the fixed `var(--card-<colour>-paper-ink)` instead (the name glyph, the placeholder art). The inks keep 3:1 or more on every page surface of their theme; the fills do not (yellow and grey vanish on paper, brown and purple on the lapis panels). A glyph on a band uses the band ink.
- `bg-vp` and `border-vp-edge` are the victory-point tablet (the military track's zone points, the tallies, the effect glyphs): a fixed printed green, the same in both themes, with `text-(--paper-bright)` numerals on it.
- `text-cinnabar-ink` is the warning and error ink for text and standalone glyphs. It follows the theme and stays readable on page surfaces and the 15% cinnabar tint; `cinnabar` itself stays the fill, border and ring colour. The fixed `--cinnabar-paper-ink` is used inside the small city wonder tile, whose paper surface stays light in both themes. Sun ink also covers the parchment surface of the age summary. Disabled shared buttons use the full-opacity `accent-soft` / `accent-soft-fg` pair, so instructional labels remain readable; a softer fill distinguishes them from enabled primary actions.
- `text-coin-ink` is the coin glyph outside the gold badges and printed coins (the player strip, the cost breakdown, the score table); `var(--coin-paper-ink)` is its fixed twin on a card face. Gold itself is under 2:1 on paper. The player crests use `text-sun-ink` and `text-moon-ink`; `text-sun` and `text-moon` are fills.
- `dark:` follows `data-theme="dark"` on `<html>`, which reflects the in-app choice, not only the system setting.
- Two screen-level variants exist: `short:` (a height of 32rem or less, such as a phone in landscape) and `split:` (room for two columns: 64rem wide, or a short landscape screen).
- Use logical properties only (`ms-*`, `pe-*`, `text-start` and so on). Padding by the physical safe-area insets is the one deliberate exception.
- The two players' crests are fixed by seat: seat 0 is the Sun (turquoise, `sun` colours) and seat 1 is the Moon (pomegranate, `moon` colours), in every mode and on every screen.

## Strings

Every user-visible string goes through `t(key, params)` from `$lib/i18n`. The English tables in `src/lib/i18n/en/` define the keys, and the compiler checks each call: an unknown key, a missing placeholder value, or a count that is not a number is a type error. Plural messages are objects of forms (`one`, `other`, exact `=0` and so on), chosen with `Intl.PluralRules`; numbers are formatted with `Intl.NumberFormat`. `i18n.locale` and `i18n.dir` are reactive, and the root layout copies them to `<html lang dir>`.

### Languages and direction

- **Locales.** `LOCALES` in `src/lib/i18n/locale.svelte.ts` lists the languages with a table: English (`en`) and Persian (`fa`). English defines the keys; the Persian table translates every one of them, following the glossary in `docs/i18n/persian.md`. To add a locale, add its code to `LOCALES`, a folder `src/lib/i18n/<code>/` with one file per English area it translates (each typed `as const satisfies Translation<typeof en>`, so a misspelt or stale key fails to compile), an `index.ts` that merges them as a `PartialLocaleTable`, an on-demand loader in `src/lib/i18n/locale.svelte.ts`, a name for the Settings row (`home.settings.language*`, written in the language itself), and its direction in `RTL_LANGUAGES` if it is written right to left.
- **On-demand messages.** English is the initial table. `i18n.set(locale)` returns a promise and loads Persian only when requested. Text, digits and direction keep the current language until the table is ready, including for a persisted choice. The table is cached, repeated requests share one load, a later English choice cancels an earlier pending switch, and failed loading keeps the working language. Tests that require Persian await the switch.
- **Per-key fallback.** A key the table leaves out falls back to English. Its plural form is chosen by English rules (the forms are English ones) and its numbers keep the locale's digits. In a right-to-left locale the fallback is marked left to right (a left-to-right isolate between two left-to-right marks), so its punctuation stays at its end and English sentences joined into one string keep their order; `isFallbackText()` tells such text apart, and `joinList` joins a list of fallback words the English way. End a sentence built from such text with `fullStop()`, never a bare `.` after it, or the stop lands at the start of the English sentence; and count letters with `stripBidiMarks()` first (CardFace's name fit does). A string param (a player's name, a card name) is isolated in a right-to-left locale, so a Latin name never trades places with the words around it. The Persian table is complete, so in practice the fallback shows only for a key added to English and not yet to Persian (a test fails until it is).
- **The language setting.** Settings has a Language row (English, فارسی), stored as `locale` in `ajayeb:settings`. The settings store requests it when it loads and on every save; text and direction change when its table is ready. The browser's language is not read. The web manifest stays English.
- **First paint.** Prerendered Home starts in English. The theme bootstrap applies the stored colour theme before paint; the root layout changes language and direction together after the requested messages load. This keeps English fallback text left to right while Persian is loading.
- **Fonts.** The self-hosted fonts are Latin subsets, so Arabic-script text falls through the font stack. For `lang="fa"`, `src/app.css` names Vazirmatn (where installed), Noto Naskh Arabic or Noto Sans Arabic, then the system fonts. No Persian font is shipped yet.
- **Direction.** The app chrome follows `i18n.dir` (logical properties, `rtl:-scale-x-100` on back and undo arrows). The board region, the card structure and the military track are `dir="ltr"` in every locale, because their layout is spatial. Show numbers through `formatNumber`, never as a bare `{n}`, so they take the locale's digits. Translated text inherits the locale direction, including sentences beginning with a Latin player name. Use `dir="auto"` only on bare player names and name fields; interpolated names already have directional isolates. Card names, categories, age labels and textual badge labels explicitly use `i18n.dir` inside the left-to-right card geometry, as do translated labels inside spatial diagram rows. Numerical markers and operators keep their spatial direction.
- **The fixture.** `e2e/specs/rtl.spec.ts` runs Home, Settings and a hot-seat game in Persian on both projects: no horizontal scroll, mirrored chrome measured against the same state in English, a left-to-right board, one move and the result screen. It also measures the visual order of Latin names in Persian pass-device logs and starter options, and checks that lobby sharing labels stay on one line at the four review sizes. The base fixture's `appLocale` option sets the language (`test.use({ appLocale: 'fa' })`).

## Icons

`src/lib/icons/svg/*.svg` are the hand-authored icon sources. Each standalone SVG has a 24x24 viewBox, or 12x12 for a `-sm` variant. The primary paint is `var(--i1, currentColor)` and optional secondary detail uses `var(--i2, transparent)`; a component can supply those tones through CSS. Silhouettes must still read with the transparent fallback. [art/vector/STYLE.md](../art/vector/STYLE.md) defines the paint, grid and size rules.

`names.ts` lists every icon name; `sprite.ts` builds the sources into one inline sprite and throws at build time if a listed source is missing or an unlisted source exists. `IconSprite.svelte` inlines it once in the root layout. `Icon.svelte` renders one icon (`<Icon name="resource-wood" />`), sized in `em`, decorative (`aria-hidden`) unless given a translated `label`.

The original vector set was drawn in M9, with hint and effect glyphs added in M10, through the Opus render and critique loop. The [vector pipeline](../docs/art/README.md#the-vector-pipeline) documents that process; `/dev/gallery` shows the icons in both themes.

## Bitmap art

The card, wonder, token, card-back, bot-avatar, victory-scene, hero, texture and app-icon art comes from the bitmap pipeline ([docs/art/bitmaps.md](../docs/art/bitmaps.md)). The app shows only approved art, through the generated index `src/lib/art/available.gen.ts` (`node tools/art/index.mjs`; never edit it by hand), and draws its procedural placeholder for every other id. Approving an asset and regenerating the index is all it takes for the art to appear: no component changes.

- `src/lib/art/lookup.ts` answers which file a frame shows: `pickArt(id, size)` prefers the requested shipped size (`'default'`, `'thumb'`), then the default, then the widest variant, and returns `undefined` when the id has no approved art. Ids are `<kind>/<slug>` (`artId`, `backArtId`, `avatarArtId` with the bot levels mapped to the apprentice, scholar and master avatars, `seatBotLevel` for the level of a room's bot seat, and `victoryArtId` for the scene of how a game ended: a draw shows `victory/draw` once one is approved and the civilian scene until then). Index paths are root-absolute, because the app is served at the site root, and end in `?v=<content hash>`, which lets the server cache them for a year. The `sizes` strings of the frames that pick from a srcset (`cardArtSizes`, `WONDER_ART_SIZES`, `tokenArtSizes`) live here too, and `artSource(id, size, sizes)` returns exactly what `ArtImage` renders, so the prefetch asks for the same file the frame will.
- `src/lib/art/ArtImage.svelte` draws one piece of art as a lazy, async-decoded, decorative `<img>` that fades in once loaded (instantly with Animation off). With no approved art, or when the file fails to load, it renders its `fallback` snippet instead, so there is never a broken image. Its `feather` prop melts the art into the paper with a CSS mask (no alpha channel, no hard rectangle): `soft` for cards and wonder panoramas, `sky` (a narrow top fade) for a painting whose subject reaches its top edge, `edge` for small thumbnails, `none` for art that is already shaped. Its `position` prop anchors the cover crop; `src/lib/art/crops.ts` holds the per-asset framing (the Colossus and the Mausoleum anchor near the top, with the `sky` fade).
- Where art shows:
  - Cards: `components/card/CardArt.svelte` at every tier but the colour band. The mini tier (the phone pyramid) and the medium tier show the 240x180 thumbnail, the full tier a srcset of both sizes chosen by width. On a mini card the art fills only the part below the 40% line, with the narrower `edge` fade, so the cost, the effect glyphs and the chain chips in the top 40% read as before. Once a card has art, the medium tier also shows the category glyph by the name, since the bitmap carries no glyph. Names break between words only, and a name whose longest word would not fit shrinks a step instead (`longestWord` in `card-style.ts`). The full card keeps its art at least 30% of its height under a two-line name, and leaves the chain-out sentence to the sheet beside it (the chain chip already shows the symbol).
  - Wonders: `WonderTile` (the draft tile with a srcset of the 480, 960 and 1440 px files, the city row with the thumbnail), framed by `crops.ts`.
  - Progress tokens: `ProgressToken` (round, in a gold ring; a srcset of the 96 and 256 px files by the medallion's width, so a DPR 3 phone draws the larger one). A token in a player's city is `owned` and shows in full colour; `taken` greys a token only where it is gone from the board.
  - Card backs: `CardBack`, under the gold frame and the numeral cartouche, which stay SVG.
  - Bot avatars: `src/lib/art/BotAvatar.svelte`, with the persona's initial as its placeholder: in each level's choice on the new-game sheet, and by a bot seat's name in `PlayerStrip` and the `CityPanel` header (their `bot` prop).
  - Victory scenes: `screens/GameOver.svelte`, a small framed scene beside the headline with the winner's crest on its lower edge, so the dialog keeps the score table and the buttons in its height.
  - The hero: Home, in a 16:9 frame above the logotype whose size never depends on the art (the eight-pointed star until `hero/hero` is approved).
  - Textures: the page behind everything (`body` in `app.css`) tiles `texture/paper` in the light theme and `texture/night` in the dark one, through `--table-texture` in `tokens.css`. Panels and cards stay solid, so no small text sits on the grain. These are the only art paths named in CSS rather than through the index; each carries its content hash, and `textures.test.ts` checks the approved asset and hash.
  - The app icon: `static/icons/` holds PNGs (the apple-touch-icon and the manifest's 192 and 512 px icons), linked from `app.html` and `static/manifest.webmanifest`, made by `node tools/art/process.mjs --app-icons`. They are the one exception to AVIF only, because iOS and the manifest need PNG.
- `src/lib/art/prefetch.ts` and `ArtPrefetch.svelte` (mounted once on the game screen) fetch the whole game's approved art after the board's first paint, one file at a time at low priority while the browser is idle: the current age's cards, the next age's, the other ages and the guilds, then every wonder, token, back and victory scene. The plan comes from the catalog of each age, never from which cards were dealt, so it depends on the age alone. Each file goes through an `Image` with the frame's own srcset and sizes, so the browser picks the file the frame will show. With Save-Data or a 2G connection it keeps the small plan (the next age's backs and card thumbnails, within 200 KB). With nothing approved the plan is empty and nothing is fetched. `docs/art/bitmaps.md` ("Caching", "Prefetch") has the details.
- `/dev/gallery` opens its Cards section with the art frames: the approved art of each kind in its real frames (mini, medium and full cards, wonder tiles, tokens as on the board, owned and taken, backs and avatars), next to one placeholder, in the current theme. `?art=card/theater,wonder/pyramids` puts named ids first. Unit tests (`src/lib/art/*.test.ts`) cover the lookup, the fallback, the crops, the textures, the app icon and manifest, and the prefetch plan, and render the frames and their consumers (the new-game sheet, the strip and panel, the result screen) on the server. The Go server's cache policy for `/art/` files is `CacheControl` in `server/internal/webdist`.

To look at art that is not approved yet, process it into a scratch directory (`process.mjs --out`), copy the AVIFs under `static/art/<kind>/`, point a scratch copy of `available.gen.ts` at them and build the test bundle. Restore the generated index and delete the scratch files before committing.

## UI lints

`scripts/lint-ui.mjs` (plain Node, no new dependencies; run by `pnpm -C web lint`, so `make lint-web` runs it too) checks two project rules that ESLint and Prettier do not:

- **Logical CSS only.** No physical Tailwind utility (`ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`, `rounded-l`, `rounded-r`, `border-l`, `border-r`, `scroll-ml-`/`mr-`/`pl-`/`pr-`, `origin-left`/`right`, `float-left`/`right`) and no physical CSS property (`margin-left`, `margin-right`, `padding-left`, `padding-right`, `border-left`, `border-right`, bare `left:`/`right:`) in `.svelte` or `.css` files under `src/`. Mark a deliberate exception with `physical-ok` on the same line (the board region and safe-area insets are the known exceptions).
- **No hard-coded English.** Every template text node and every `aria-label`, `title`, `alt` and `placeholder` string literal in a `.svelte` file must go through `t()`. The rule reads the whole template, so it also catches text on a line of its own and text next to an expression (`{count} coins`). `<code>` and `<kbd>` content is exempt (it is literal, not translatable), and a line can opt out with `i18n-ok` when the text is genuinely not shipped UI copy, such as a `/dev` fixture label.

Both rules are pure functions (`findPhysicalCssViolations`, `findHardcodedTextViolations`) exported from `lint-ui.mjs` and unit-tested from `src/lib/lint-ui.test.ts` (kept under `src/` so Vitest's `include` picks it up).

A third rule lives in `src/lib/lint-ui.test.ts` itself, so `make test-web` enforces it: **no native `title` attribute** (`title="..."`, `title={...}` or the `{title}` shorthand) on any element in any `.svelte` file under `src/`. Use the tooltip helper instead (see Tooltips); an iframe takes `aria-label` for its accessible name. SVG `<title>` elements are elements, not attributes, and stay allowed.

## App shell

`src/service-worker.ts` is the app-shell service worker. SvelteKit builds it to `/service-worker.js`, a stable name, and registers it on every page load; the Go server revalidates that file on every load, so a new build reaches the browser at once. The app then opens without a network, and shows its own offline state: a game needs the server, so a room page shows the session's "Offline" state, and Home, the rules and Settings show the one-line notice `components/shell/OfflineNotice.svelte` (the layout passes it the browser's online state from `svelte/reactivity/window`, and never on a game page). The cache policy by URL is the pure module `src/lib/sw/policy.ts`, unit-tested in `policy.test.ts`.

- **Precache.** On install it caches, in a cache named after the build's version (`ajayeb-shell-<version>`): every `/_app/immutable/` file of this build (code, CSS and the content-hashed fonts), the generic shell (`shell.html`, under `/shell.html`), and the stable-named statics that `kit.serviceWorker.files` in `svelte.config.js` lets through: the favicon, the web manifest and the app icons. A new version deletes the older shell caches when it activates.
- **Page loads** go network first. The cached shell answers only when the network fails or takes more than 4 seconds. Every network response, including an HTTP error, is returned unchanged. Offline app routes get the generic shell and the client router renders the route; an online Home load receives its prerendered HTML.
- **Build files and statics** come from the precache, then the network.
- **Art** (`/art/...?v=<hash>`) is cached as it is shown, cache first, in `ajayeb-art`, which outlives versions because its URLs carry their hash, and keeps at most 150 entries, the least recently used going first. Art is never precached (D24): the idle prefetch in `lib/art/prefetch.ts` warms it. Cache lookup and LRU refresh run in one transaction queue, so concurrent offline requests cannot observe a hit while its entry is being reordered. Art without a `v` goes to the network.
- **Sounds** (`/sfx/...?v=<hash>`) use a separate 24-entry runtime cache, `ajayeb-sound`, with the same serialized LRU policy. They are never precached. Only an audio-unlocking gesture starts their fetches; their content hashes let cached files survive shell updates.
- **Never touched:** `/ws`, `/api` and everything under it (`/api/dev/*` included), `/health`, the worker script, `/_app/version.json`, other origins, non-GET requests and range requests. The worker never calls `respondWith` for them, so they behave as if there were no worker.
- **Updates.** A new version waits until the next full page load with no game page (`/play/<code>`) open. Game pages hold a shared Web Lock (pending lock requests count as game intent too), so client-side navigation into a game is visible to the worker too. Where Web Locks are unavailable or their owner IDs cannot be matched to the worker's window client IDs, all open app tabs hold updates back, and the browser activates the new version once they close. A window's load URL cannot safely identify a game opened by client-side navigation. It never guesses that a focused game tab is the one being replaced: another game tab must keep its original chunks. Close game tabs or leave their games before reloading Home to apply a waiting update. There is no update notice.
- **Tests.** End-to-end specs block the worker by default: `e2e/fixtures/base.ts` sets Playwright's `serviceWorkers: 'block'` for the default context and blocks registration in the contexts `newDeviceContext` makes by hand. `e2e/specs/shell.spec.ts` allows it and checks the install, the hashed fonts, the offline Home and room page, the untouched endpoints and the stable names. `e2e/specs/sound-files.spec.ts` also allows it for the runtime-audio case, checking that install caches no audio, the first audition caches the set, and those files remain available offline. In Chrome DevTools, Application > Service workers shows the worker, and "Bypass for network" turns it off while developing.

## Fonts

Fraunces (600, headings) and Inter (400, 600 and 700, the interface) are self-hosted under the SIL Open Font License 1.1. The WOFF2 files live in `src/lib/fonts/`, with the license texts beside them. The `@font-face` rules in `src/app.css` point at them with relative URLs, so Vite emits each one as `/_app/immutable/assets/<name>.<hash>.woff2`: a URL that changes with the file, which the server caches for a year and the service worker precaches (see App shell). The licenses are also served at `/fonts/OFL-Fraunces.txt` and `/fonts/OFL-Inter.txt` from `static/fonts/`. The two Home fonts are preloaded from `src/routes/+layout.svelte`, which imports their build-generated URLs, rather than from `src/app.html`, which cannot name a hashed URL. Repeat loads use the precache. The WOFF2 files are Latin subsets made by `font-sources/subset.sh` from the original TTFs in `font-sources/`. Upstream: Fraunces 1.000 from github.com/undercasetype/Fraunces and Inter 4.001 from github.com/rsms/inter.

## Hint and layout follow-ups (M10.hints-followups)

Board progress tokens open TokenSheet on a tap when no token pick is pending.
Long-press keeps the tooltip gesture; the sheet shows the token effect and
its server-provided hint values. Changing rooms, including a rematch, closes
the old token sheet. The pending token pick lists both seats'
values when the view supplies them, and CitySheet lists all enabled threats.

Use `formatSigned` beside `formatNumber` for displayed signed numbers. It
formats with Intl, replacing an ASCII minusSign part with U+2212 while
preserving a locale's own minus sign and digit shapes.

The recap's static board hooks are `data-recap-tick` (`up` or `down`) on a
trade-price caret, `data-recap-price` on a changed affordability badge,
`data-recap-trace` on an emptied slot and `data-recap-revealed` on a fresh
card. Marks last until the viewer's move ends, and follow the recap family
and the local board-marks switch. The result screen's `data-end-review`
contains the review when the viewer's own move ended the game.

The first-time tips also explain `ghostLoot` (military), `freeChain` (costs),
`hourglass` (wonders), `guildBack` (guilds) and `lawLaurel` (science). They use
the existing once-per-device `ajayeb:tips` seen-set and link to Rules.

Home remembers each live room’s latest server-sent age and, for bot games,
the bot level beside Continue. Saved-room changes synchronize between tabs,
including removal when a game finishes. Older saved entries still open
without summary details. Online presence sits beside the name in both the
phone strip and the desktop city header. Logs opened from mid-game scenarios
use the displayed age until an age boundary is recorded.

Review follow-ups keep card faces and board progress-token rows `dir="ltr"`
wherever they appear, including a mini card in a Persian card sheet. The
tooltip preview panel also keeps its positioning box left to right while
its captions follow the locale. Bare player names
and name fields use `dir="auto"` locally. Sentence endings, joins and label/detail
punctuation live in the message tables; `fullStop`, `sentences`,
`joinPhrases` and `labelDetail` preserve the English fallback isolates.

Only the More in Rules link row intercepts the pointer. The rest of a
linked tooltip lets a neighboring card receive clicks immediately and
hover after a bounded 300 ms pause. Movement refreshes this hover-intent
grace so a slow crossing can still reach the link. Touch

guild and actual starter-choice tooltips show the existing compact rules

Queued ordinary moves still catch up without animation. If a zero-delay
