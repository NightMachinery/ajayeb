# web: the Ajayeb client

The browser client: a SvelteKit 2 single-page app with Svelte 5 runes, Tailwind 4, Vite 8 and TypeScript 6.0. It is thin on purpose. The Go server holds the only rules engine; this app renders the views the server sends and sends back action keys. See [AGENTS.md](../AGENTS.md) for the conventions and [docs/architecture.md](../docs/architecture.md) for the data flow.

## Running it

Heavy commands go through the root `Makefile`, which wraps them in the memory guard (`tools/heavy.py`):

- `make check-web` runs `svelte-kit sync` and `svelte-check` (the type gate).
- `make lint-web` runs ESLint and `prettier --check`.
- `make test-web` runs the Vitest unit tests (one worker thread).
- `make build-web` writes the static build to `web/build/`; `make build` embeds it in the Go binary.
- `python3 self_host.py dev-start` runs the Go server and the Vite dev server together (see `make dev`).

The package scripts behind them are `dev`, `build`, `preview`, `check`, `lint`, `format` and `test`.

Ports: Vite dev listens on 38952 and `vite preview` on 38953. Both forward `/ws`, `/api` and `/health` to the Go server at `http://127.0.0.1:38951`, or to `AJAYEB_SERVER` when that is set.

## Layout

- `src/app.html` is the page template. Its inline script applies the stored theme before the first paint, so the page never flashes the wrong theme.
- `src/app.css` imports Tailwind and the tokens, declares the fonts, maps the tokens to Tailwind utilities, and holds the base styles (the `100dvh` app shell, the safe-area variables `--safe-t`, `--safe-r`, `--safe-b`, `--safe-l`, focus rings and the styles for Animation off).
- `src/lib/styles/tokens.css` is the single source of colour, type and motion tokens, in OKLCH. Cards keep their paper colours in both themes; only the table surfaces change, from an ivory manuscript page (light) to lapis night (dark).
- `src/lib/i18n/` holds the message tables and `t()`.
- `src/lib/ui/` holds UI state classes, such as the theme (`theme.svelte.ts`) and the safe-area override (`safe-area.ts`), and small display mappers such as the military track's side (`track.ts`) and the online helpers (`online.ts`: the room-code input normaliser and alphabet, the invite link, seat presence and its changes, the QR path).
- `src/lib/dev/flags.ts` decides whether the `/dev` routes exist.
- `src/routes/` holds the pages. `/` is Home, `/play/<code>` is a room, `/rules` is the rules reference, and `/dev/*` holds the developer pages.
- `static/` is served as is: the fonts with their licenses, the favicon, and the approved bitmap art under `static/art/` (see Bitmap art).
- `font-sources/` keeps the original TTF fonts and `subset.sh`, which rebuilds the shipped WOFF2 subsets in `static/fonts/`.

## Session: talking to the server

`src/lib/session/` is the client's whole connection layer. It decides nothing about the game: what may be played is the view's `choices`, what it costs is their cost breakdowns, and whether this client may act comes from the state frame. [docs/protocol.md](../docs/protocol.md) is the contract it implements.

- `transport.ts` defines the Transport (send, onMessage, onState, close, and an optional `reconnect` that drops the socket and opens a new one). `ws-transport.ts` is the WebSocket to `/ws` on the page's origin, with reconnects (exponential backoff with jitter, capped at 15 s; no retry after a 1008 `protocol` or `bad-hello` close). The browser's `offline` event drops an open socket at once, so the page shows the offline state and sends nothing, and its `online` event retries without waiting for the backoff. `fixture-transport.ts` answers from recorded frames, for dev pages and tests, and `scripted-transport.ts` is driven by hand in unit tests.
- `identity.ts`: the identity token in `localStorage` (`ajayeb:token`, 22 base64url characters, never logged), a random client id per page load, and the display name (`ajayeb:name`).
- `session.svelte.ts`: the Session. It says `hello` on every socket, creates and joins rooms, and sends acts and undos with the tab's `seq` counter and the current version as `base`. It keeps the latest state frame and view in `$state.raw` (replaced whole), the connection state (`connecting`, `open`, `reconnecting`, `offline`), the pending request with a `slow` flag after 300 ms, the last refusal as a message key, and `canAct`. After a reconnect it joins again and re-sends the pending request unchanged. A request the server dropped under its frame rate limit (`reject rate` naming its seq) is re-sent unchanged after a short pause, up to three times, before the refusal shows. `catalogStale` is set when a view's `catalogHash` differs from the client's catalog.
  - `setName(name)` changes the display name the next `hello` sends. When `hello` already went out under another name, it reconnects, so the room shows the new name at once.
  - In a bot room an undo can cross the bot's answer: the server refuses it as `stale` because the answer moved the version. The Session then waits for the fresh state and, if that state still offers undo, sends the undo once more with the same seq and the fresh version as `base`. Only a second refusal shows the stale message.
  - `rematch()` asks for the rematch (a spectator only follows one). `rematchAsked` says this tab asked, so the room page moves to the rematch room as soon as the server's `created` names it; the other player sees the offer on the game-over dialog instead. A request lost to a reconnect is sent again after the join.
- `presenter.svelte.ts`: the Presenter, which holds the frame on screen and moves it forward one queued frame at a time (capture hook, swap, tick, play hook). It has no animations yet, but it paces a bot's answer: a frame that answers a thinking frame waits until the thinking frame has been up `minThinkingMs`, and when the answer takes a card or drafts a wonder it sits in `preview` for `preRollMs` while the old frame stays up. Both settings may be functions; `app.svelte.ts` reads them from the animation speed (`botDwellMs` and `botPickMs` in `ui/motion.svelte.ts`: 700 ms and 300 ms at normal speed, 300 ms each with animation off). A frame with others queued behind it is never paced, `fastForwardAfter` catches up after a reconnect, `hurry()` shows a held answer at once (an undo pressed during the dwell) and `clear()` forgets the room when the game screen goes away. Input is open when `presenter.idle && session.canAct`, so it stays locked through the dwell and the preview.
- `rooms.svelte.ts`: the rooms this browser has played (`ajayeb:rooms`: code, mode and last seen).
- The Session also carries a game's hint settings: `hints` (the room's), `admin` (this user may change them), `canSetHints`, and `roomLog` (the room-level log entries, which `LogSheet.svelte` shows among the moves). `setHints(next)` sends a `hints` frame through the same pending slot and `seq` counter as an act. A `create` without settings takes them from the `defaultHints` option, which `app.svelte.ts` points at the local default below.
- `context.ts` shares a page's Session and Presenter with its components (`setGameContext`, `getSession`, `getPresenter`); `app.svelte.ts` holds the app's one live connection, opened the first time a page needs it.
- `test-hook.ts` defines `window.__ajayeb` for end-to-end drivers (see [docs/testing.md](../docs/testing.md)).
- `DebugBoard.svelte` is a plain view of a room with every choice as a `data-act` button. No page uses it any more; it stays for debugging.

`src/lib/hints/` holds the hint settings on the client (docs/dev/decisions.md D23). `families.ts` lists the twelve families and has the pure helpers: the defaults per mode, the editor's rows, the one-line summary, and `visibleFamilies(roomSettings, localHide)`, the families a screen may show (the game's settings minus what this player hides). `local.svelte.ts` holds two stores in `localStorage`: the local default (`ajayeb:hints`), which a new-game sheet starts from and which is written when a game is created and when its admin changes the settings mid-game (the advisor kept per mode, the other families shared), and the local hide (`ajayeb:hintsHidden`: hidden families, and whether hint marks show on the board). `log.ts` puts the room log among the game log's lines. The components are in `src/lib/components/hints/`: the settings editor, the new-game sheets' collapsible section, the lobby's summary, and the game menu's Hints item with its sheet ("On my screen" holds the local hide).

`src/lib/catalog/` has typed lookups (`cardBySlug`, `wonderBySlug`, `tokenBySlug`) over `src/lib/wire/catalog.gen.ts`, the presentation catalog that `make gen` writes from the engine's data.

The pages: `/play/<code>` joins a room and shows the game screen (`Room.svelte`). A first visit with no stored name, to a room this browser has not created or played, shows `screens/NamePrompt.svelte` first, and only then joins (a join takes the seat under the name at once). A room this browser makes is remembered in the saved rooms the moment it exists: the Session does it on `created` (Home's games and a rematch it asked for) and `createDevRoom` on the dev endpoint's answer, so these open without the prompt. The saved list is read once per code, so a finished game dropped from it never turns back into the prompt. An end-to-end spec that opens a dev room it made with its own HTTP request, in a fresh browser, has to store a name (`ajayeb:name`) first. A room that cannot be opened shows `screens/RoomError.svelte`, with a friendly message for the server's code and a way Home. Home's "Play online" opens `screens/OnlineSheet.svelte` (name, crest, Create, which sends `create` with mode online) and "Join with a code" opens `screens/JoinSheet.svelte` (six characters from the server's alphabet, case-insensitive; a pasted invite link works too); `/dev/new?mode=hotseat|ai|online` creates a room and opens it (with `seed=` or `scenario=`, through the server's dev endpoint); `/dev/fixture/<name>` shows a recorded game state in the game screen with no server.

## The game screen

`src/lib/components/game/GameScreen.svelte` is the board of every mode. It takes the page's Session and Presenter and an `onhome` callback, and decides nothing about the game.

- **Layout.** One markup, with CSS grid areas chosen by `breakpoints.viewport` (`src/lib/layout/breakpoints.svelte.ts`) through a `data-layout` attribute. Phone portrait: top bar, opponent strip, military track and progress tokens, structure (taking the remaining height), own strip, turn bar. Phone landscape: the compact track and tokens move into the top bar, and the strips take side columns. Tablet: stacked, with city bands under each strip. Desktop: city panels in 300 px side columns, 380 px from 1600 px wide. The shell is `100dvh` and never scrolls. During the wonder draft the area between the top bar and the turn bar holds the Draft screen.
- **Player strips** (`city/PlayerStrip.svelte`, phones). The two strips have the same layout and fit in two short rows, so neither ever scrolls. Row 1: the crest (and the bot's avatar), the name (which opens the city sheet), presence, thinking, a military danger shield, the owned progress tokens, coins and victory points (`city/Tally.svelte`: a gold coin pill and a green laurel pill), and the wonder button. Row 2: the five resource chips (production, then the trade price as a coin) and the science count (a green glyph and "n/6"). In phone landscape, where a strip is a narrow side column, the rows wrap: the first always breaks after the name and puts the owned tokens last, so both strips have their tallies and wonder button on one line of their own. Danger warnings (`view/threats.ts`) only show while the game runs and the condition has not already been met.
- **Wonders.** Each player has one wonder button (`wonder/WonderButton.svelte`) reading built/total. When a wonder of the player to move can be built now (`buildableWonders` in `view/wonders.ts` reads the view's `wonder` choices, nothing else), it has an accent ring and a dot. It opens `sheets/WonderListSheet.svelte`, the list of that player's wonders (`wonder/WonderList.svelte`). Each row shows the art (or its placeholder), the name, the cost, a one-line effect and one status: "Built with <card>", "Can build now" or "Not built". The desktop city panel uses the same rows. A row that can be acted on opens the wonder sheet, whose Back button returns to the list.
- **Who sits where.** The board region is `dir="ltr"`. The player is at the bottom (or on the left); a spectator sees seat 0 there. In hot-seat the board faces the player to move on phones and stays fixed elsewhere, with the active panel lit; the setting overrides both.
- **Bottom sheets** (`shell/Sheet.svelte`, used by every sheet) close on Esc, a backdrop tap or a swipe down on phones (`shell/sheet-drag.ts`: from the handle, or from the panel when it is scrolled to its top). The panel and the root element set `overscroll-behavior`, so a pull never reloads the page.
- **The card sheet** (`CardSheet.svelte`) opens on a tapped slot. It shows the card at full tier, its category and effect, the cost breakdown from the matching choice (or disabled choice), the opponent's price and the discard gain, and the Build, Discard and Build a wonder buttons, each with its key as `data-act`. A covered card shows its cover count, no actions, and what each player would pay once it is uncovered, from the server's `costs` on the slot. Build a wonder steps to `WonderStep.svelte`, which lists the player's wonders with cost and affordability. `card-actions.ts` only sorts the view's choices for one card; it never parses keys or computes costs.
- **Wonder first.** Picking one of your wonders from the wonder list (or from the desktop panel) opens `sheets/WonderSheet.svelte`. "Build this wonder" starts the pick mode: the turn bar asks for a card (with Cancel), takeable cards carry a wonder badge, and tapping one opens the card sheet to confirm. Both flows send `wonder:<wonder>:<card>`.
- **Committing.** Hot-seat and bot rooms send on the tap; online rooms use `ConfirmButton` when the confirm-moves setting asks for it, in the card sheet, in the wonder draft and in every pending choice's commit button. One rule (`game/act-button.ts`) decides each move button's label, whether it is disabled and whether it takes the confirm step, for the card sheet (`ActionButton.svelte`), the pending panels (`choices/CommitButton.svelte`) and the starter choice. On send the sheet closes, the slot shows the pending outline and input locks until the ack; after 300 ms the turn bar shows the slow state. A refusal shows its message above the turn bar.
- **The turn bar** (`hud/TurnBar.svelte`) renders one state from `view/turn.ts`. On a phone it is slim (about 40 px plus the safe area), and its buttons keep a 44 px tap target. A wonder's extra turn reads "Play again (Appian Way)" (or "Sun plays again" in hot-seat) for the whole extra turn: `playAgainFrom` reads it from the events this screen has seen, because `view.extraTurn` only means "plays again once this turn is over" and is already cleared when the extra turn starts. A page opened or reloaded during an extra turn has not seen the grant and shows the ordinary turn.
- **Toasts** never cover the opponent's strip or the military track. A player's own move gets no toast (they just made it), in every mode; the one exception is a choice the server skipped because it had no option (nothing to destroy, an empty discard pile), which the player could not foresee: a toast gives the line that says why, without the move's own line and without an Undo. On a phone and a tablet they sit just above the turn bar. On a desktop and in phone landscape (outside the draft) they sit at the foot of this player's own column, clear of the structure's bottom row, the cards a player can take.
- **Undo** is the game menu's "Undo last move" (greyed out, with the reason under it, while undo is not possible now), the top bar's arrow, the U key and Ctrl+Z (Cmd+Z on a Mac), in hot-seat and bot rooms only; online rooms have no undo. The bot and hot-seat sheets have an "Allow undo" switch (on by default): the game is created with it (`allowUndo` in `create`), the server fixes it for the game's life and reports it as `room.allowUndo`, and a game created with it off shows no undo anywhere (menu, top bar, keyboard, pass-device screen). The game menu's Hints sheet shows the setting read-only. The switch is remembered per mode on this device (`session/undo-default.svelte.ts`, `ajayeb:allowUndo`), next to the hints' local default, and the Session's create reads it. In a bot room undo also takes back the bot's reply (the server does that); pressed while a bot answer is held for its dwell, the answer shows first and is then taken back.
- **Against the bot.** The bot's seat is named by its persona (`names.ts`: Apprentice for easy, Scholar for normal, Master for hard) wherever a seat name shows. While it thinks, the turn bar reads "<persona> is thinking" and its strip or panel shows `hud/ThinkingDots.svelte`, which stands still with Animation off. During the Presenter's preview the slot it takes, or the draft offer it picks, carries `data-bot-pick` and a ring in its crest colour (`botPick` in `card-actions.ts` finds it from the answer's events).
- **The military track** has the capital of the seat at the bottom (or on the left) at its left end: a player at the Moon sees it mirrored, with the pawn, the zones and the looting tokens following (`ui/track.ts`). Spectators and the Sun see it as the view states it. It is drawn as its 19 spaces (`view/track-cells.ts`): zones shaded deeper toward each capital with a line at every boundary, each looting token on its own space (3 or 6) showing the coins it takes, and each zone's points on a laurel tablet under the bar. The desktop adds a legend line.
- **The opponent move summary** (`game/MoveSummary.svelte`, one `game/MoveSummaryLine.svelte` per line, `view/move-summary.ts`): when a live frame hands the turn back after the other side's moves, a popup lists them in order, consolidated (a bot's reply, both moves of an extra turn and the choices inside a turn are one summary): the card and how it was taken, the coins paid and the trade part, other coin changes, the pawn, looting, a science pair, the token taken, a wonder and what it destroyed or revived, an age change. It opens once the Presenter shows that frame (in hot-seat after the pass-device screen, for the player who moved before), never for history a join, a resync or an undo replays, and never during the wonder draft (`summaryTrigger`). It is a DismissLayer: any tap closes it and is swallowed, and Escape closes it. It sits over the structure's top on a phone and over the viewer's own column on wide screens and in phone landscape. Settings' "Show opponent move in detail" (`showOpponentMove` in `ajayeb:settings`, on by default) stops it opening by itself; the top bar's eye (`data-control="move-summary"`, next to the log, shown once the other side has moved) always opens the latest one (`latestSummary`). Below 26rem the top bar drops its settings gear to make room (Settings stays in the game menu). The panel ends with an empty `data-summary-review` slot for the move review line. The e2e base fixture turns the popup off for every spec but `move-summary.spec.ts`.
- **The game menu** (the top bar's first button, every mode) holds Home, Settings and the log, and Forfeit while the game runs. Forfeit opens `game/ForfeitConfirm.svelte`, which names the winner (and, in hot-seat, the player to move, who is the one forfeiting); only its confirm button sends `resign:<seat>` (`Session.resign`). The game-over dialog then says who forfeited. Home leaves the room; the room stays on Home's Continue list until its game ends, and the hint under Home that says so is gone once the game is over.
- **Online rooms.**
  - While the room is in the lobby, the game screen shows `screens/Lobby.svelte`: the code in large type, the invite link with Copy link (and a toast) and Share (only where `navigator.share` exists), and a QR code drawn from `uqr`, which loads only when the lobby shows. The lobby turns into the draft when the friend's join arrives.
  - The other player's strip or panel shows `hud/PresenceDot.svelte`: a filled dot when connected, a dashed ring and the word "away" when not, so it reads in greyscale. A toast says when they join, leave or come back, and while they are away the turn bar's waiting text says so.
  - While this tab's own connection is down, the ConnectionPill (icon only in the top bar below desktop widths) and the turn bar say so, the board stays open for inspection, and every move button reads "Waiting for connection" and is disabled. The fresh state after the reconnect restores the board.
  - A spectator sees the board read-only, with "Watching" in the turn bar, a note in the card sheet and no actions. Players see the spectator count (`hud/SpectatorCount.svelte`) in the top bar.
  - Rematch on the game-over dialog asks for the rematch room and moves there. The other player sees "<name> wants a rematch" and a Join the rematch button; a spectator gets Watch the rematch.
- **Hot-seat** shows the pass-device screen between turns of different players when the setting is on (by default on touch screens), with the last move's summary and an undo for the previous player (only in a game that allows undo).
- **Draft, choices and game over.** `screens/Draft.svelte` fills the main area during the wonder draft. `choices/ChoiceHost.svelte` stays mounted through the play (it shows pending choices and the bar that says who starts a new age), except while the pass-device screen is up, since its modal panels would cover that screen. Its bars (`choices/PeekBar.svelte` with `inline`) sit in the flow just above the turn bar, so they cover neither the takeable cards nor the player's own strip; the who-starts bar also closes on the first tap on the structure. `screens/GameOver.svelte` is its own centred dialog once the game is over. They take `{view, canAct, onact}` and `{view, onrematch?, onhome}`.
- **Test contract.** Structure cards keep `data-card` and action buttons `data-act`. Further hooks for drivers: `data-control="wonder-step"`, `"wonder-build"`, `"wonder-pick-cancel"`, `"undo"`, `"log"`, `"settings"`, `"move-summary"` (the top bar's eye), `"open-city"`, `"menu"`, `"menu-home"`, `"menu-settings"`, `"menu-log"`, `"menu-undo"` (with `data-undo-reason` under it while greyed out), `"menu-forfeit"`, `"allow-undo"` (the new-game sheets' switch, in a `data-allow-undo` row), `"forfeit-confirm"`, `"forfeit-cancel"`, `"wonders"` (a strip's wonder button), `"wonder-list-back"`; `data-forfeit-confirm` on the confirm step; `data-wonder-list` (the seat) on the wonder list; `data-wonder` on wonder buttons and `data-buildable` on those that can be built now; `data-covered-cost` (`own` or `other`) on a covered card's cost lines; `data-military-danger` on a strip's danger shield; `data-marked` on pickable slots; `data-bot-pick` on the slot or draft offer a bot is about to take; `data-thinking` (the bot's seat) on the game screen and on the thinking seat's panel; `data-turn` (the TurnState kind) on the turn bar; `data-left-seat` and `data-mirrored` on the military track; `data-pass-device` on the pass screen; `data-toast` on toasts; `data-move-summary` (the mover's seat, with `data-plies`) on the move summary and `data-summary-line` (the line's kind) on its lines; `data-setting="show-opponent-move"` on its Settings switch. Online: `data-lobby`, `data-room-code`, `data-invite-link`, `data-qr` and `data-lobby-seat` in the lobby, `data-control="copy-link"`, `"share-link"`, `"lobby-home"`; `data-presence` (`connected` or `away`) on presence dots and seat panels; `data-away` on the turn bar while the waited-for player is away; `data-spectators` on the spectator count; `data-watching` on the spectator's card-sheet note; `data-rematch` on the rematch button; `data-home-hint` on the menu's Home hint; `data-undo-setting` (`on` or `off`) on the Hints sheet's read-only undo setting; `data-name-prompt`, `data-name-input`, `data-control="name-submit"`; `data-online-sheet`, `data-control="online-create"`, `"online-join"`; `data-join-sheet`, `data-code-input`, `data-control="join-submit"`, `"home-join"`; `data-room-error` and `data-control="error-home"`.

The `/dev/gallery` page has a Game screen section that shows recorded states (draft, Age I, Age II, Age III, a pending choice, game over, and the online lobby, opponent-away and watching states) in frames of a phone and a desktop size. Its Online section shows the lobby (a fixed fake code and QR, also reconnecting), the name prompt, the online and join sheets, the room error, and the connection states of the pill, the presence dot and the turn bar.

## Tooltips

Tooltips never use the native `title` attribute. Give an element one with the `tooltip` attachment from `src/lib/ui/tooltip.svelte.ts`:

```svelte
<span {@attach tooltip({ text: t('board.resource.chip', { resource, count, price }) })}>
```

Pass `undefined` instead of the content for no tooltip (a conditional one). The content has `text` (already through `t()`, short), an optional `diagram` snippet (a small concept picture whose labels are translatable text beside the SVG, never baked into it), an optional `stack` of linked previews, an optional `rulesId` (the rules reference section a later "More in Rules" link opens), and an optional `actionable` override for the touch model.

- **The layer.** `components/shell/TooltipLayer.svelte` is mounted once, in the root layout. It installs the gestures (`installTooltipGestures`) and draws the one open tooltip in a manual popover, so it shows above an open sheet too. The bubble (`TooltipBubble.svelte`) and the stack (`TooltipStack.svelte`) are plain leaf components that the gallery also renders standalone.
- **Fine pointer.** A hover shows the tooltip after 450 ms; moving to the next anchor within 300 ms of a tooltip closing shows the next one at once. Keyboard focus (focus-visible only) shows it at once. Escape closes it, and only it: the sheet beneath stays open. A mouse click acts as usual and closes any open tooltip, a keyboard focus one included, so a tooltip never lingers over the menu or sheet the click opened and takes its Escape.
- **Touch (model B).** A tap on an element with no action shows its tooltip. An element is actionable when it or an ancestor is a button, a link, a form control, a `summary`, a `label`, an element with an interactive role or a `data-act` (`ACTIONABLE_SELECTOR` in `ui/tooltip-gesture.ts`), and is not disabled. An actionable element keeps its tap and shows its tooltip on a 500 ms long-press, whose release is swallowed so it never acts. A finger that moves more than 10 px cancels the press, so a long-press never fights scrolling, and the browser's own long-press menu and callout are suppressed on anchors. Any tap while a tooltip is open closes it and is swallowed: neither the press nor its click reaches the page.
- **Innermost wins.** The anchor is the innermost registered element under the pointer or finger: a chain chip inside a card slot shows the chip's tooltip, and the rest of the slot the slot's own. One tooltip shows at a time.
- **Stacks.** A stack is a second panel of up to two linked previews, joined to the bubble by a short gold connector: beside the bubble when both fit side by side (from 640 px wide), otherwise on the bubble's far side from the anchor, so the bubble and its arrow always stay next to the anchor. A `card` item draws a real full-tier `CardFace` at 140 px; a `custom` item renders the caller's snippet. One tap closes the bubble and its stack together. The chain chips use it now (`ui/chain-links.ts`): a chain-out chip says which card it makes free and stacks that card, and a chain-in chip says which card provides the symbol and stacks that card.
- **Where a stack fits next** (for the content slices): the "free through <card>" line of the card sheet's cost breakdown and the structure's chain badge (stack the card in the player's city that provides the symbol); a wonder row's "Built with <card>" (the card spent on it); a resource chip whose trade price a card fixes at 1 coin (that card); a science symbol in the tracker (the city cards that show it, so a pair is visible); a guild's or commercial card's "per card" effect (the counted cards, as a custom snippet); and the log's and the opponent move summary's entries (the card built or discarded).
- **Placement.** `ui/tooltip-place.ts` is pure, unit-tested math: above the anchor by preference, flipped below when it does not fit, shifted sideways so it never leaves the viewport less the safe-area insets (measured by a probe element), with the arrow pointing at the anchor. The boxes are placed in viewport pixels in a `dir="ltr"` overlay, while their text follows the page's direction. A scroll carries the tooltip with its anchor, and closes it once the anchor leaves the viewport; a resize closes it.
- **Motion.** The tooltip fades in over `--dur-fast`, which follows the game's Animation setting; with Animation off it appears at once.
- **Accessibility.** The bubble has `role="tooltip"` and the id `ajayeb-tooltip`; a focusable anchor gets `aria-describedby` pointing at it while it shows. Micro-elements inside a focusable card (its chips and glyphs) are not focusable themselves: the card's own accessible name describes them, so there is no tab stop per symbol.
- **The dismiss layer.** `components/shell/DismissLayer.svelte` is a floating panel (a manual popover, centred by default; pass position classes to move it) with the same rule: any tap closes it and is swallowed, and Escape closes it. With `keepInside`, taps inside the panel reach their targets (a coach mark's Next button) and only taps outside close it. It is made for the opponent move summary and the tutorial's coach marks. `installDismiss` and `swallowClick` in `ui/dismiss.ts` are the behaviour on its own, for any other overlay.
- **Gallery and tests.** `/dev/gallery/tooltips` shows every variant: plain text, parameters, a diagram, the stacked chain chips, a chip inside an actionable card, a button, the bubble and stack standalone, and the dismiss layer. `?show=<id>` opens the tooltip of the element marked `data-tip-demo="<id>"` for screenshots, and `?edges` adds stacked chain chips at the viewport's corners. `e2e/specs/tooltips.spec.ts` covers hover, focus, Escape and innermost resolution on the desktop project, and tap, long-press and the swallowed tap on the mobile project. Test hooks: `data-tooltip` on every registered anchor, `data-tooltip-layer`, `data-tooltip-bubble` (with `data-side`), `data-tooltip-stack`, `data-card-preview` on a stacked card, `data-chain` and `data-chain-direction` on chain chips, and `data-dismiss-layer`.

## The rules reference

The rules of the base game, in our own words, live in two places that work together:

- `src/lib/i18n/en/rules.ts` holds the text, one key per paragraph, list item or definition. It is written from `docs/rules/` (never from the rulebook; see `docs/legal.md`). Card, wonder and token names are never written there: a `{placeholder}` names them, filled from the existing name keys.
- `src/lib/components/rules/sections.ts` arranges those keys into sections, each with a stable id: `goal`, `setup`, `turn`, `costs`, `military`, `science`, `wonders`, `tokens`, `guilds`, `age-end`, `scoring` and `glossary`. Tooltips and hints link to these ids, so add new ids rather than renaming one. `sections.test.ts` checks that the ids are unique, that every key exists and that every placeholder is filled.

They show in two ways:

- **The page `/rules`**, linked from the Home footer (`data-control="home-rules"`). It has a table of contents, and each section is a deep link such as `/rules#military`.
- **The in-game overlay**, opened by the game menu's Rules item (`data-control="menu-rules"`) without leaving the game. With room for two columns (`split`) it is a side panel over the opponent's column, so the board stays visible and usable; on a phone it is a bottom sheet (`shell/Sheet.svelte`, swipe down to close). Both have the contents as a row of chips and Close (`data-control="rules-close"`); Escape closes them too.

Any component can open the overlay at a section with `openRules('military')` from `components/rules/rules-overlay.svelte.ts` (no section opens it at the top, or where the reader left it). The first call loads the overlay in its own chunk and mounts it once at the end of `<body>`, so no screen has to place it, and it closes itself when the page changes. The diagrams (`MilitaryDiagram`, `TradeDiagram`, `ScienceDiagram`) are built from the board's own components and the icon sprite, with every label as translatable text. Test hooks: `data-rules-page` on the page, `data-rules-overlay` (`drawer` or `sheet`) on the overlay, `data-rules-panel` on its body, `data-rules-section` on each section, `data-rules-toc-item` on each contents entry and `data-rules-diagram` on each diagram. `/dev/gallery` has a rules section under Screens with the diagrams, the panel at two widths, and buttons that call `openRules()`.

## Sound and haptics

`src/lib/fx/` plays short cues when a frame's events arrive. There are no audio files: `sfx.ts` synthesizes seven cues with WebAudio (card slide, coin clink, flip, war drum, science chime, fanfare, draft tick). `cues.ts` is the pure, unit-tested mapper from a frame's events to cues and a vibration pattern. The Presenter calls `playFrameFx` once per shown frame.

- Only live events play. The first snapshot of a room, another room's frame, and a frame whose version does not move forward (an undo, a resync) are silent.
- Each cue kind plays at most once per frame, 90 ms apart, in the order of its first event. `play(cue, { delayMs })` takes a delay, so animations can retime cues later.
- Settings: Show opponent move in detail (on by default; see the game screen's move summary). Sound (off by default) with a Quiet, Medium or Loud step, and Vibration (on by default, shown only where `navigator.vibrate` exists). Sound does not follow the Animation setting. The AudioContext starts only inside a user gesture: the Sound switch itself, or any later pointer or key press.
- Haptics: 8 ms when a card or wonder is taken, a short pattern when the pawn moves, a longer one for looting.
- Test hook: `window.__ajayebFx.cues()` and `.haptics()` list what would have played (a cue only while Sound is on, a vibration only while Vibration is on), and `.clear()` empties both. `e2e/specs/sound.spec.ts` reads it.
- `/dev/gallery` has a sound board under Screens, with a button per cue.

## Styling

- Tailwind's default colour palette is switched off. Use the semantic utilities, such as `bg-table`, `bg-panel`, `text-fg`, `text-fg-muted`, `border-rule`, `bg-accent` and `text-on-accent`, so every colour follows the theme. The palette and game colours are there too (`bg-card-red`, `text-sun-ink`, `bg-res-wood` and so on). The resource colours come in two kinds: `bg-res-wood` and the like are the resource tile fills, and `text-res-wood-ink`, `text-res-clay-ink`, `text-res-stone-ink`, `text-res-glass-ink` and `text-res-papyrus-ink` are the theme-aware inks for a resource glyph drawn straight on a page surface (paper, panel, parchment, or the night panels in dark mode). The inks keep 3:1 or more against those surfaces; the fills do not (papyrus and glass vanish on paper, wood on the night panels). A glyph on a resource tile or a card uses the card ink.
- The card colours come in the same two kinds, plus a third. `bg-card-brown` to `bg-card-purple` are the band fills. `text-card-brown-ink`, `text-card-grey-ink`, `text-card-blue-ink`, `text-card-green-ink`, `text-card-yellow-ink`, `text-card-red-ink` and `text-card-purple-ink` are the theme-aware inks for a category glyph (or any glyph inked by its card colour) on a page surface, such as the city chips, the score table and the discard filter. On a card face, which stays paper in both themes, use the fixed `var(--card-<colour>-paper-ink)` instead (the name glyph, the placeholder art). The inks keep 3:1 or more on every page surface of their theme; the fills do not (yellow and grey vanish on paper, brown and purple on the lapis panels). A glyph on a band uses the band ink.
- `text-coin-ink` is the coin glyph outside the gold badges and printed coins (the player strip, the cost breakdown, the score table); `var(--coin-paper-ink)` is its fixed twin on a card face. Gold itself is under 2:1 on paper. The player crests use `text-sun-ink` and `text-moon-ink`; `text-sun` and `text-moon` are fills.
- `dark:` follows `data-theme="dark"` on `<html>`, which reflects the in-app choice, not only the system setting.
- Two screen-level variants exist: `short:` (a height of 32rem or less, such as a phone in landscape) and `split:` (room for two columns: 64rem wide, or a short landscape screen).
- Use logical properties only (`ms-*`, `pe-*`, `text-start` and so on). Padding by the physical safe-area insets is the one deliberate exception.
- The two players' crests are fixed by seat: seat 0 is the Sun (turquoise, `sun` colours) and seat 1 is the Moon (pomegranate, `moon` colours), in every mode and on every screen.

## Strings

Every user-visible string goes through `t(key, params)` from `$lib/i18n`. The English tables in `src/lib/i18n/en/` define the keys, and the compiler checks each call: an unknown key, a missing placeholder value, or a count that is not a number is a type error. Plural messages are objects of forms (`one`, `other`, exact `=0` and so on), chosen with `Intl.PluralRules`; numbers are formatted with `Intl.NumberFormat`. `i18n.locale` and `i18n.dir` are reactive, and the root layout copies them to `<html lang dir>`.

## Icons

`src/lib/icons/svg/*.svg` are the hand-authored icon sources: one standalone `<svg viewBox="0 0 24 24">` (or `0 0 12 12` for a `-sm` variant) per file, two-tone through `fill="var(--i1, currentColor)"` for the primary shape and `var(--i2, rgba(128,128,128,0.65))` for the secondary accent. The `--i2` fallback is an opaque neutral grey, not `currentColor` or `transparent`: nothing in the app sets `--i1`/`--i2` yet, and a transparent or same-colour fallback made the secondary detail invisible wherever it sits over an `--i1`-filled region of the same resolved colour (opacity cannot separate two coincident fills of one colour). `names.ts` lists every icon name; `sprite.ts` builds them into one inline sprite (`import.meta.glob('./svg/*.svg', { query: '?raw' })`) and throws at build time if a name has no source file or a source file is missing from the list. `IconSprite.svelte` inlines the sprite once, in the root layout; `Icon.svelte` renders one icon (`<Icon name="resource-wood" />`), sized in `em`, decorative (`aria-hidden`) unless given a `label`.

This is the placeholder set for M5: simple, clean, geometric shapes, never copied or traced from official iconography. The M9 milestone replaces it through its own Opus render-critique loop (see `art/vector/` once that milestone starts); `/dev/gallery` renders every icon at a glance for a visual check in both themes.

## Bitmap art

The card, wonder, token, card-back, bot-avatar, victory-scene, hero, texture and app-icon art comes from the bitmap pipeline ([docs/art/bitmaps.md](../docs/art/bitmaps.md)). The app shows only approved art, through the generated index `src/lib/art/available.gen.ts` (`node tools/art/index.mjs`; never edit it by hand), and draws its procedural placeholder for every other id. Approving an asset and regenerating the index is all it takes for the art to appear: no component changes.

- `src/lib/art/lookup.ts` answers which file a frame shows: `pickArt(id, size)` prefers the requested shipped size (`'default'`, `'thumb'`), then the default, then the widest variant, and returns `undefined` when the id has no approved art. Ids are `<kind>/<slug>` (`artId`, `backArtId`, `avatarArtId` with the bot levels mapped to the apprentice, scholar and master avatars, `seatBotLevel` for the level of a room's bot seat, and `victoryArtId` for the scene of how a game ended: a draw shows `victory/draw` once one is approved and the civilian scene until then). Index paths are root-absolute, because the app is served at the site root.
- `src/lib/art/ArtImage.svelte` draws one piece of art as a lazy, async-decoded, decorative `<img>` that fades in once loaded (instantly with Animation off). With no approved art, or when the file fails to load, it renders its `fallback` snippet instead, so there is never a broken image. Its `feather` prop melts the art into the paper with a CSS mask (no alpha channel, no hard rectangle): `soft` for cards and wonder panoramas, `sky` (a narrow top fade) for a painting whose subject reaches its top edge, `edge` for small thumbnails, `none` for art that is already shaped. Its `position` prop anchors the cover crop; `src/lib/art/crops.ts` holds the per-asset framing (the Colossus and the Mausoleum anchor near the top, with the `sky` fade).
- Where art shows:
  - Cards: `components/card/CardArt.svelte` at every tier but the colour band. The mini tier (the phone pyramid) and the medium tier show the 240x180 thumbnail, the full tier a srcset of both sizes chosen by width. On a mini card the art fills only the part below the 40% line, with the narrower `edge` fade, so the cost, the effect glyphs and the chain chips in the top 40% read as before. Once a card has art, the medium tier also shows the category glyph by the name, since the bitmap carries no glyph. Names break between words only, and a name whose longest word would not fit shrinks a step instead (`longestWord` in `card-style.ts`). The full card keeps its art at least 30% of its height under a two-line name, and leaves the chain-out sentence to the sheet beside it (the chain chip already shows the symbol).
  - Wonders: `WonderTile` (the draft tile with a srcset, the city row with the thumbnail), framed by `crops.ts`.
  - Progress tokens: `ProgressToken` (the 96 px thumbnail, round, in a gold ring). A token in a player's city is `owned` and shows in full colour; `taken` greys a token only where it is gone from the board.
  - Card backs: `CardBack`, under the gold frame and the numeral cartouche, which stay SVG.
  - Bot avatars: `src/lib/art/BotAvatar.svelte`, with the persona's initial as its placeholder: in each level's choice on the new-game sheet, and by a bot seat's name in `PlayerStrip` and the `CityPanel` header (their `bot` prop).
  - Victory scenes: `screens/GameOver.svelte`, a small framed scene beside the headline with the winner's crest on its lower edge, so the dialog keeps the score table and the buttons in its height.
  - The hero: Home, in a 16:9 frame above the logotype whose size never depends on the art (the eight-pointed star until `hero/hero` is approved).
  - Textures: the page behind everything (`body` in `app.css`) tiles `texture/paper` in the light theme and `texture/night` in the dark one, through `--table-texture` in `tokens.css`. Panels and cards stay solid, so no small text sits on the grain. These are the only art paths named in CSS rather than through the index; `textures.test.ts` checks they are approved art.
  - The app icon: `static/icons/` holds PNGs (the apple-touch-icon and the manifest's 192 and 512 px icons), linked from `app.html` and `static/manifest.webmanifest`, made by `node tools/art/process.mjs --app-icons`. They are the one exception to AVIF only, because iOS and the manifest need PNG.
- `src/lib/art/prefetch.ts` and `ArtPrefetch.svelte` (mounted once on the game screen) fetch the next age's approved backs and card thumbnails while the current age is played, one file at a time when the browser is idle, within 200 KB per age. The client cannot know which cards the next age deals, so it takes them in catalog order until the budget runs out. With nothing approved the plan is empty and nothing is fetched.
- `/dev/gallery` opens its Cards section with the art frames: the approved art of each kind in its real frames (mini, medium and full cards, wonder tiles, tokens as on the board, owned and taken, backs and avatars), next to one placeholder, in the current theme. `?art=card/theater,wonder/pyramids` puts named ids first. Unit tests (`src/lib/art/*.test.ts`) cover the lookup, the fallback, the crops, the textures, the app icon and manifest, and the prefetch plan, and render the frames and their consumers (the new-game sheet, the strip and panel, the result screen) on the server. The Go server's cache policy for `/art/` files is `CacheControl` in `server/internal/webdist`.

To look at art that is not approved yet, process it into a scratch directory (`process.mjs --out`), copy the AVIFs under `static/art/<kind>/`, point a scratch copy of `available.gen.ts` at them and build the test bundle. Restore the generated index and delete the scratch files before committing.

## UI lints

`scripts/lint-ui.mjs` (plain Node, no new dependencies; run by `pnpm -C web lint`, so `make lint-web` runs it too) checks two project rules that ESLint and Prettier do not:

- **Logical CSS only.** No physical Tailwind utility (`ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`, `rounded-l`, `rounded-r`, `border-l`, `border-r`, `scroll-ml-`/`mr-`/`pl-`/`pr-`, `origin-left`/`right`, `float-left`/`right`) and no physical CSS property (`margin-left`, `margin-right`, `padding-left`, `padding-right`, `border-left`, `border-right`, bare `left:`/`right:`) in `.svelte` or `.css` files under `src/`. Mark a deliberate exception with `physical-ok` on the same line (the board region and safe-area insets are the known exceptions).
- **No hard-coded English.** Every template text node and every `aria-label`, `title`, `alt` and `placeholder` string literal in a `.svelte` file must go through `t()`. The rule reads the whole template, so it also catches text on a line of its own and text next to an expression (`{count} coins`). `<code>` and `<kbd>` content is exempt (it is literal, not translatable), and a line can opt out with `i18n-ok` when the text is genuinely not shipped UI copy, such as a `/dev` fixture label.

Both rules are pure functions (`findPhysicalCssViolations`, `findHardcodedTextViolations`) exported from `lint-ui.mjs` and unit-tested from `src/lib/lint-ui.test.ts` (kept under `src/` so Vitest's `include` picks it up).

A third rule lives in `src/lib/lint-ui.test.ts` itself, so `make test-web` enforces it: **no native `title` attribute** (`title="..."`, `title={...}` or the `{title}` shorthand) on any element in any `.svelte` file under `src/`. Use the tooltip helper instead (see Tooltips); an iframe takes `aria-label` for its accessible name. SVG `<title>` elements are elements, not attributes, and stay allowed.
