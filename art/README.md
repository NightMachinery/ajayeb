# art: original art for Ajayeb

Two pipelines produce Ajayeb's original art. This directory holds the
bitmap one's inputs and committed outputs; `art/vector/` (a separate
milestone) holds the hand-authored SVG set's style guide, specs and logs.
See [docs/art/bitmaps.md](../docs/art/bitmaps.md) for how the bitmap
pipeline runs end to end, and [docs/legal.md](../docs/legal.md) for the
license and what this art is never allowed to copy.

## Layout

- `style.md`: the style prefix, palette, motifs, do/don't list and the
  per-kind prompt templates. This is the single source every generated
  prompt is built from.
- `subjects.json`: one subject (a short scene description) and an accent
  hue per asset id, keyed `<kind>/<slug>` (`card/lumber-yard`,
  `wonder/pyramids`, `back/age1`, ...). Human-written and human-edited;
  `tools/art/manifest.mjs` reads it but never writes it.
- `manifest.json`: generated by `tools/art/manifest.mjs` from the engine's
  presentation catalog plus `subjects.json`. Tracks every asset's
  generation size, crop, status (`todo`, `generated`, `approved`,
  `rejected`, `needs-human`), attempt count, prompt amendment and shipped
  byte counts. Committed, because it is the pipeline's record of what has
  and hasn't been approved.
- `refs/`: the style anchors the owner picked from the pilot, one small
  JPEG per kind (`card-anchor.jpg`, `wonder-anchor.jpg`,
  `token-anchor.jpg`), with a README naming each source attempt and what it
  anchors. They are review references: `generate.mjs` sends one to Codex
  only when run with `--ref`, and the batch never does.
- `originals/<kind>/<id>.png`: approved bitmap originals, committed as
  generated (no hand-editing). `web/static/art/**.avif` is derived from
  these by `tools/art/process.mjs`; a shipped file is never hand-edited,
  only regenerated from its original.
- `LICENSE`: the CC BY 4.0 notice covering this directory, its shipped
  derivatives and the hand-drawn SVG icon set.

## What is not here

- Raw, not-yet-approved attempts live outside the repository, under
  `${AJAYEB_RUN_DIR:-~/tmp/agents/ajayeb}/art-work/raw/<kind>/<slug>/<n>.png`,
  so a rejected attempt never touches git history.
- Contact sheets live under `${AJAYEB_RUN_DIR:-~/tmp/agents/ajayeb}/art-work/sheets/`,
  also outside the repository.
- Review decisions are a reviewer's own `decisions.jsonl`, applied with
  `tools/art/apply-review.mjs`; nothing about an in-progress review is
  committed here either, only its effect on `manifest.json`'s statuses.

## Running the pipeline

See [docs/art/bitmaps.md](../docs/art/bitmaps.md) for the full walk-through
and [tools/art/README.md](../tools/art/README.md#bitmap-pipeline) for each
script's flags. In short: `manifest.mjs` (rebuild the manifest) →
`generate.mjs` (one Codex `image_gen` call per asset, through
`python3 tools/heavy.py run --kind codex`) → `gate.mjs` (an objective
full-bleed check) → `sheet.mjs` (a contact sheet to look at) → a reviewer
writes `decisions.jsonl` → `apply-review.mjs` (apply it) → `process.mjs`
(ship the AVIFs for an approved asset, mapping its paper tone onto
`--card-paper` and, for a token, masking to its own painted rim) →
`index.mjs` (regenerate `web/src/lib/art/available.gen.ts`).
